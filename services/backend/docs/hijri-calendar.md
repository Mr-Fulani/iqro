# Общий календарь Хиджры

## Как работать в админке

Откройте **Мусульманский календарь → События календаря**
(`/admin/calendar/calendarevent/`). Восемь исходных событий создаются миграцией:
Рамадан, последние десять ночей, два праздника, Арафа, Ашура, дни ташрика и белые дни.
Чтобы изменить описание, откройте существующую запись: не создавайте её дубль.

Для нового события:

1. Выберите месяц **по Хиджре**, либо «Каждый месяц» для повторяющегося правила.
2. Укажите первое и последнее число включительно. Для одного дня — одинаковое число.
   Отметка 30-го числа не появляется в месяце из 29 дней.
3. Выберите понятный тип отметки: значимая дата, добровольный пост или дни без поста.
   Ежемесячное правило при необходимости можно исключить из Рамадана.
4. Заполните название и пояснение на RU/EN/AR/TR, название источника и HTTPS-ссылку.
   Сохранить черновик можно без полного перевода; опубликовать — нельзя.
5. После редакционной проверки включите «Показывать на сайте и в приложении».
   Технический код создаётся автоматически. Менять его вручную не требуется.

Для снятия отметки выключите публикацию, сохранив запись. Удаление не требуется.
Изменения приходят на сайт и в новый мобильный клиент через общий публичный API.
Онлайн-обновление обычно занимает до 5 минут; офлайн остаётся последний корректный
каталог. Веб-клиент обновляет открытую видимую страницу каждые 5 минут; мобильный
также имеет кнопку обновления. HTTP/CDN-кеш может продлить видимость старого ответа.

Не вводите григорианский год вручную: ежегодные соответствия рассчитываются.
Это не редактор официальных местных объявлений о начале Рамадана и не универсальный
календарь произвольных однократных мероприятий. Такие сценарии требуют отдельной модели.

## Контракт и достоверность

- Публичные read-only `/api/v1/calendar/catalog` и `/api/v1/calendar/month`.
  Второй принимает `date=YYYY-MM-DD` **либо** `year=1448&month=9`; `adjustment=-2..2`.
  Смешивание вариантов/неверная дата возвращает 400. Авторизация не нужна.
- `schema_version=1`, `method=ummalqura-hijri-3.0.1`, SHA-256 версии каталога и ETag.
  Ответ месяца включает полный согласованный снимок каталога, ISO-даты гражданских
  дней и коды событий. Неделя: ISO Monday=1. Закат не угадывается сервером.
- Таблица `data/ummalqura-v1.json` совпадает с `hijri 3.0.1` Flutter (BSD-2-Clause,
  `data/HIJRI-LICENSE.txt`). 1356–1500 AH, 14.03.1937–16.11.2077 без поправки.
- Проверенные ссылки и собственные краткие пояснения находятся в `data/events-v1.json`.
  Встроенный мобильный seed идентичен исходному API. Редактирование админки не требует
  пересборки seed/APK. `ops/calendar/export_seed.py` служит воспроизводимости исходного
  набора, не синхронизирует продакшн-БД и не перезаписывает изменённые файлы.
- Добровольный пост не отмечается 1 Шавваля и 10–13 Зуль-хиджа независимо от удаления
  праздников администратором. Последние десять ночей не приравниваются к гарантированной
  дате Ляйлят аль-Кадр. Нужна содержательная проверка новых событий, не только URL.

## Деплой и откат

Две добавочные миграции создают таблицу и исходные записи через `get_or_create`,
сохраняя существующие редакторские записи. Обратный seed — noop. Для отката приложения
достаточно прежнего кода: новая таблица не мешает ему. **Не откатывайте initial-миграцию**,
так как это удалит таблицу и изменения редактора. Перед обновлением — проверенный backup.

Проверки: backend `tests/test_calendar.py`, mobile `calendar_catalog_test.dart`,
web `e2e/calendar.spec.ts` (четыре языка, RTL, выбор дня/месяца/поправки, network retry).
