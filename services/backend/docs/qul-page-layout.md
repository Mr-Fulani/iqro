# Структура страниц QUL для Web и Flutter

Текст, глифы, цвета и изображения слов остаются из выбранного ресурса
Quran.Foundation. Порядок слов внутри страницы, строки, заголовки и басмала
задаются фиксированными пакетами QUL. Это согласованный вариант композиции,
а не утверждение о совпадении двух разных редакций на каждом переносе строки.

| Quran.Foundation ID | Пакет QUL | Страниц |
|---|---|---:|
| 2, 10, 11, 12 | [QPC V1](https://qul.tarteel.ai/resources/mushaf-layout/15) | 604 |
| 1, 4, 5, 16 | [QPC V2](https://qul.tarteel.ai/resources/mushaf-layout/10) | 604 |
| 19 | [QPC V4 Tajweed](https://qul.tarteel.ai/resources/mushaf-layout/19) | 604 |
| 6, 14 | [Qudratullah IndoPak 15](https://qul.tarteel.ai/resources/mushaf-layout/12) | 610 |
| 7, 15 | [Taj IndoPak 16](https://qul.tarteel.ai/resources/mushaf-layout/11) | 548 |

Для QPC Nastaleeq (14/15) сознательно используется полная композиция
Qudratullah/Taj с собственным шрифтом QPC. Выгрузка `qpc-nastaleeq-15-lines.db`
от 14.09.2026 не подключена: в ней только один заголовок суры и пять повторно
назначенных слов. Это другой профиль, не исправление текста Корана.

## Запуск разработчиком

JSON-профили находятся в Python-пакете `modules/quran/qul_layouts` и входят
в репозиторий и backend image. После обычного запуска с наполненной БД QF
они применяются автоматически в API страниц. Отдельного входа в QUL,
ручного скачивания архивов, миграции или изменения локальной БД не требуется.
Первый запуск и загрузка исходных данных QF описаны в основном README.

Страница API содержит `layout` версии 1 с явными строками и ссылкой/SHA-256
источника. `words` уже упорядочены по этой структуре; исходные номера сохранены
в `source_line_number` и `source_position_in_page`. Перед применением проверяется
полное равенство множеств слов страницы и отсутствие дублей. Если будущая
выгрузка меняет состав страницы, API сохраняет исходные слова и возвращает
`layout: null`, не применяя несовместимый профиль частично.

Оба клиента используют одинаковые строки и признаки центрирования. Обычные
строки выравниваются промежутками между словами без растяжения глифов; первые
две страницы центрируются целым блоком, как в живом preview QUL. Это правило
первых страниц уточняет старые флаги SQLite. Во Flutter версия кэша страниц
повышена до `qul-layout-v1`; прежние файлы не удаляются. После обновления
мобильной сборки для первого получения нового контракта нужен доступ к API.

## Воспроизводимость и проверка

Генератор `ops/qf-mushaf-renderer/build_qul_layouts.py` читает SQLite только
в режиме read-only. Ему нужны пять перечисленных пакетов, словарь
`indopak-nastaleeq.db` ([QUL 59](https://qul.tarteel.ai/resources/quran-script/59))
и полные snapshots `mushaf-{ID}.json` всех 13 ресурсов.

```bash
python3 ops/qf-mushaf-renderer/build_qul_layouts.py \
  /path/to/qul-databases /path/to/qf-snapshots \
  services/backend/src/quran_backend/modules/quran/qul_layouts
```

Словарь QUL содержит 83 668 записей, QF — 83 665: `بَعْدَ مَا` в 2:181,
8:6 и 13:37 хранится соответственно двумя и одной записью. Генератор явно
сопоставляет эти три случая через суру/аят/позицию, а не общим смещением ID.
На snapshots от 13.09.2026 проверены все 7 752 страницы: в каждом варианте
сохранены все 83 665 слов/маркеров ровно по одному разу, без перехода между
страницами. Порядок строк берётся из выбранного QUL-пакета.

Тесты backend проверяют все профили, главы 1–114, отсутствие басмалы перед
9-й сурой и отказ от частичной разметки несовместимого snapshot. Web/Flutter
проверяют выравнивание, масштаб, центрирование и попадание в аят.

## Границы точности

SQLite задаёт структуру и выравнивание, но не содержит координат печати,
базовых линий картинок или орнаментов заголовков. Заголовки и басмала набраны
официальным Uthmanic Hafs; декоративные рамки оригинала не воспроизводятся.
Unicode-шрифты и PNG слов не следует объявлять пиксельно точным факсимиле.
Проверка каждой печатной страницы по независимому изображению не выполнена.
