# Инвентаризация Мусхафов — 2026-09-07

Это аудит доступности, **не акт установки новых изданий**. Рабочий мобильный
Мусхаф остаётся `madani-hafs` с растровыми страницами и отдельной картой аятов.
Его не переименовываем в другие издания. Существующие offline-загрузки сохраняются.

## Наш backend / Quran.Foundation

Проверен публичный staging endpoint `/api/v1/quran/foundation/mushafs`.
Все четыре записи относятся к Hafs, 604 страницы, 15 строк — это не четыре
разных риваята. Во всех `native_rendering.available=false`.

| Source | Издание | Web | Что отсутствует для native |
|---|---|---|---|
| 1 | QCF V2, печать 1441 AH | Постраничные WOFF2 | Опубликованный проверенный native bundle |
| 5 | KFGQPC HAFS | Unicode WOFF2 | Native страницы/раскладка и точная карта аятов |
| 11 | Uthmani Recite Quran tajweed images | Asset URL недоступен | Подтверждённый источник изображений и native bundle |
| 19 | QCF V4 Tajweed | Постраничные COLRv1 WOFF2 | Проверенный цветной native render и карта аятов |

Дополнительный **клиентский долг**: `MushafVariant.supportedOnMobile` пока всегда
`false`; `native_rendering` не разбирается мобильной моделью. Backend-публикация
сама по себе не откроет издание в приложении. Нужно реализовать edition-aware
manifest/cache/page renderer и ayah hit testing, затем убрать запрет для
проверенных возможностей. Нельзя безусловно заменить `false` на `true`.

Существующий [backend pipeline](../../../services/backend/docs/qf-native-mushaf-pages.md)
публикует растры, но готовность связки «тот же аят → выделение → аудио → подробности»
надо проверить отдельно для каждого издания и версии.

## Публичные репозитории

### [quran/quran.com-images](https://github.com/quran/quran.com-images)

Полезен генератором страниц и координат по глифам, в том числе подходом к точной
геометрии выделения. Это инструментарий, а не готовый каталог всех риваятов.
Нужно закрепить конкретные входные шрифты/данные и проверить соответствие
изданию; подключение другого font-файла не превращает его в проверенный Мусхаф.

### [JMApps/mymushaf](https://github.com/JMApps/mymushaf)

Проверено дерево commit `1d040f68d284f8e6db515157f8425abfefd78df6`:

- 604 файла `assets/pageFonts/p1.ttf` … `p604.ttf`, вместе **208 121 760 байт**;
- `assets/databases/mushaf_database.db` — **20 221 952 байта**;
- дополнительные шрифты `uthmanic_hafs_v_22.ttf`, `qcf_bsml.ttf`, `surah_name_v4.ttf`,
  отдельный шрифт названий джузов;
- в исходниках модели страницы есть glyph/word, line_number, first/last_word_id,
  is_centered и отдельные типы строк: сура, басмала, аят.

Это перспективный **набор TTF + согласованная база глифов/строк** для отдельного
native font renderer. Переносить только TTF недостаточно: glyph-коды нужно читать
из соответствующей базы и правильно распределять по страницам/строкам.
Просмотр схемы моделей не равен проверке содержимого всей БД или 604 страниц.
Полный набор пока не скачан и не установлен; цифры получены из Git tree API.

### [JMApps/quran](https://github.com/JMApps/quran)

Проверено дерево commit `f08556a57d2af6c98baf8b5f2f854058925e17c4`:
постраничные TTF и `assets/databases/quran.db` (**19 279 872 байта**).
Размеры шрифтов отличаются от `mymushaf`; смешивать эти два набора нельзя.
Повторное наличие шрифтов не доказывает другое издание/риваят.

README этих проектов не содержит достаточного описания происхождения каждого
font/content asset. Для публичного релиза фиксируем provenance и применимые
условия конкретного набора; не выдаём публичность GitHub за проверенный sign-off.
Фотографии чтецов и UI-шрифты из сторонних проектов в приложение не копировались.

## Следующий конкретный этап

1. Закрепить согласованный набор TTF + glyph DB и его происхождение (начать с
   `mymushaf`, не скачивать все 208 МБ до проверки первых страниц).
2. Проверить схему БД, Quran verse/page identities и шрифты на контрольных
   страницах 1, 2, 3, 50, 255, 604; сопоставить с исходным приложением/страницей.
3. Прототип native renderer: масштаб, RTL, номера аятов, басмала/заголовки,
   landscape/portrait без растяжения и без системного font fallback.
4. Получать прямоугольники аятов из фактической раскладки; короткий тап,
   удержание, фон аята и аудио должны ссылаться на одну верную verse identity.
5. Только после сравнения — backend manifest с checksums/размерами, загрузка
   пакетами, изолированный edition/version cache и атомарное включение издания.
6. Полный набор страниц, offline/restart/low-memory/device QA и редакционный
   sign-off. До этого новые варианты не рекламируются как готовые пользователю.
