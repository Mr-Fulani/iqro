# IQRO Mobile

Нативный мобильный клиент IQRO на Flutter для Android, iPhone и iPad. Все платформы
используют один Dart-код и действующие API-контракты платформы, хранят пользовательские
изменения локально и синхронизируют их после восстановления сети.

## Возможности

- Коран: читалка, 13 макетов Мусхафа Quran Foundation, переводы и тафсиры, закладки, заметки
  и цветные выделения аятов, картинка «Поделиться аятом». Вверху вкладки «Коран» два
  выпадающих списка: сура (номер арабскими цифрами ١٢٣ и название) и аят этой суры; выбор
  аята открывает Мусхаф или текст на нём. Джуз, хизб, руб и страница — в «Быстром переходе»
  (значок слоёв в шапке). Свайп по тексту вправо открывает чистый арабский текст, влево —
  Мусхаф; в конце суры — карточка «Следующая сура», после 114-й — «Конец Корана». Можно
  выделить и прослушать слово или отрывок аята. На экране чистого арабского текста — проверка
  чтения вслух (раздел ниже). Подробнее —
  [docs/mushaf/reader-controls.md](../../docs/mushaf/reader-controls.md) и
  [docs/mushaf/word-range-playback.md](../../docs/mushaf/word-range-playback.md).
- Аудио: каталог чтецов, фоновое воспроизведение и экран блокировки, офлайн-пакеты, фоны
  плеера с эквалайзером.
- Время намаза: локальный расчёт, напоминания с азаном Мекки или Медины, кибла, месячный
  календарь, виджет; календарь Хиджры.
- План чтения с ростом финиковой пальмы, заучивание, ду‘а «Хисн аль-Муслим» и коранические.
- «Обучение намазу»: курс по ханбалитскому мазхабу на четырёх языках, офлайн-пакет картинок.
- «Курсы» в «Ещё»: курс таджвида и тематические курсы с видео и конспектами.
- Объявления: пузырь на главной и лента «Что нового».
- «Имена Аллаха» в «Ещё»: колесо имён, карточка имени с озвучкой, прогресс в аккаунте.
- В «Ещё» — карточка «Скоро»: «Книги · Квизы».
- Четыре языка интерфейса (RU/EN/AR/TR) с RTL.

Чего нет по сравнению с сайтом и что ещё не сделано — [docs/tech-debt.md](../../docs/tech-debt.md).

## Быстрый запуск на Android

Заполните ключи в backend `.env` по [корневой инструкции](../../README.md).
`make mobile-run` автоматически запускает backend, применяет миграции и подготавливает
Коран, ду’а, переводы, тафсиры, аудио и мобильные страницы, затем запускает Flutter.

Нужны Flutter 3.41.4 (версия CI), Android SDK и эмулятор либо устройство с USB-отладкой.

```bash
# Из корня репозитория; backend и данные готовятся автоматически:
make mobile-run
```

Debug по умолчанию использует `APP_ENV=local`: Android-эмулятор — `http://10.0.2.2:8000`,
Android-телефон по USB и iOS Simulator — `http://127.0.0.1:8000` (тип Android-устройства
определяется при запуске; для USB `make mobile-run` сам выполняет
`adb reverse tcp:8000 tcp:8000`). Для телефона по Wi-Fi укажите IP компьютера:

```bash
make mobile-run MOBILE_ARGS="--dart-define=API_BASE_URL=http://192.168.1.20:8000"
```

Замените IP своим и добавьте его в `DJANGO_ALLOWED_HOSTS` backend `.env`, затем выполните
`make dev-up`. Телефон и компьютер должны находиться в одной сети.

HTTP разрешён только для local/debug и локальных адресов. Profile/release сохраняют
требование HTTPS и явного окружения. Медиа с относительными URL загружаются с того же
адреса backend. Ключи Quran.Foundation не передаются в Flutter.

В разделе «Аудио» карточка с круглым аватаром является основной кнопкой запуска:
тап выбирает доступный вариант чтения, продолжает текущую суру (либо открывает
Аль-Фатиху), запускает воспроизведение и сразу показывает полный плеер. Над сеткой
работает фильтр по виду чтения; по умолчанию выбран «Муратталь», а недоступные в
каталоге виды не показываются. Несколько стилей одного чтеца остаются одной персоной
в соответствующих фильтрах, поэтому дубли аватаров внутри одного вида не создаются.
Развёрнутый плеер показывает фактический битрейт и позволяет выбрать только опубликованные
для текущего трека варианты `economy`, `standard` или `high`. Выбор хранится на устройстве;
если нужного варианта нет у другой записи, используется назначенный бэкендом default без
ошибки воспроизведения.

В «Настройки → Офлайн-хранилище» перечислены все полные и частично загруженные пакеты,
их фактический размер на устройстве, заявленный полный размер и состояние. До начала загрузки
размер берётся из проверенного manifest и показывается в отдельном подтверждении. Общий лимит
приложения — 3 ГБ; автоматического удаления нет, каждый конкретный пакет удаляется только после
подтверждения. Активная офлайн-запись сначала корректно останавливает плеер.

## Чёткость и поворот Мусхафа

Читалка отображает все 13 макетов Quran.Foundation (548, 604 или 610 страниц).
Для шрифтовых макетов Flutter загружает официальный TTF, включая COLRv1 таджвид;
для трёх графических макетов — PNG отдельных слов. Строки масштабируются равномерно
без изменения пропорций букв. Нажатия попадают по границам слов. Подсветка аята
(аудио, выделение, закладки, заметки) рисуется одной фигурой: каждое слово занимает всю
высоту строки и половину промежутков до соседей, поэтому между словами и строками нет
полос, а соседние аяты стыкуются без наложения.
Альбомный режим сохраняет пропорции каллиграфии и допускает вертикальную прокрутку.

Каталог, индекс аятов и страницы получает локальный API. При пустом каталоге приложение
показывает отсутствие данных; для подготовки достаточно `make up` в корне репозитория.
Смена макета сохраняет ссылку на аят, а номер страницы определяется по его индексу.
Закладки и прогресс остаются в каноническом корпусе.

Открытые страницы, индекс и ресурсы сохраняются на устройстве: файлы проверяются SHA-256,
запросы одного ресурса объединяются, версии данных не смешиваются. Первое открытие
требует сети. Массовая загрузка полного офлайн-пакета для новых 13 макетов пока не
предусмотрена; интерфейс объясняет кеширование по мере чтения. Ранее опубликованные
растровые наборы сохраняют прежние проверки WebP и установку полного офлайн-пакета.
[Каталог макетов и проверка](../../docs/quran-foundation-mushafs.md).

## Локальный debug APK

Для физического Android-телефона по USB сначала настройте обратный порт:

```bash
adb reverse tcp:8000 tcp:8000

flutter build apk --debug \
  --dart-define=APP_ENV=local \
  --dart-define=API_BASE_URL=http://127.0.0.1:8000

adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

- application ID: `forum.iqro.app`;
- минимальная версия Android определяется поддерживаемой версией Flutter;
- local используется по умолчанию только в debug-режиме;
- release-сборка без явных `APP_ENV` и `API_BASE_URL` намеренно не завершит
  инициализацию, а production принимает только `https://iqro.forum`;
- `APP_DOWNLOAD_URL` задаёт встроенную запасную ссылку для функции «Поделиться».

Debug APK подписывается стандартным отладочным ключом. Release-сборка не использует
debug-подпись: CI или локальный защищённый контур должен передать `android/key.properties`
и keystore. Секреты не должны попадать в Git.

## iPhone и iPad

Требуются полный Xcode 26+, Ruby 3.2+ (в CI — 4.0.1) и Bundler 4.0.3.
CocoaPods 1.17.0 и его зависимости закреплены в `Gemfile.lock`; команды `make mobile-ios-*`
устанавливают их в `vendor/bundle` и запускают через `bundle exec`.
Apple Developer signing нужен только для установки на физическое устройство или публикации.
Если используется Homebrew Ruby, сначала добавьте его в `PATH`:

```bash
brew install ruby
export PATH="$(brew --prefix ruby)/bin:$PATH"
gem install bundler -v 4.0.3
# Из корня репозитория: backend и данные также готовятся автоматически.
make mobile-ios-run
```

Проверить конфигурацию и собрать локальный debug target отдельно:

```bash
make mobile-ios-config-check
cd clients/iqro_mobile && bundle exec flutter build ios --debug --no-codesign --dart-define=APP_ENV=local
```

iOS target имеет bundle ID `forum.iqro.app`, поддерживает iOS/iPadOS 15+, UIScene,
фоновое аудио, локальные уведомления и локализованные permission-тексты RU/EN/AR/TR.
Геопозиция запрашивается только во время использования приложения для расчёта времени
намаза; фоновый location-доступ не включён.

Аккаунт-зависимое обслуживание (sync, auth refresh и перепланирование уведомлений)
выполняется при запуске и каждом возврате приложения на передний план. Периодическая задача
Workmanager не планируется, а регистрация из прежних версий снимается при запуске
(`background_work.dart`): отдельный Dart isolate нельзя безопасно согласовать с
одновременным logout/handoff без межпроцессного durable fence.
Уже поставленные системные уведомления продолжают работать без открытого приложения;
на iOS горизонт плана ограничен 8 днями и продлевается при следующем открытии/возврате.

Фирменные app icon и launch mark для обеих платформ воспроизводимо экспортируются из
одной геометрии командой `cd clients/iqro_mobile && swift tool/generate_app_icons.swift`.

## Окружения без flavors

Отдельные flavors не нужны: один и тот же код компилируется с явной конфигурацией.

```bash
# Production AAB; без keystore получится только неподписанный compile-check
make mobile-android-production

# Production iOS compile-check; без signing и загрузки в App Store Connect
make mobile-ios-production
```

`APP_ENV=production` принимает только `https://iqro.forum`. Debug-сборка использует
локальный API; на Android-эмуляторе это `http://10.0.2.2:8000`, на Android-телефоне по USB
и iOS Simulator — `http://127.0.0.1:8000`.

## Проверки

```bash
make mobile-check
```

Mobile CI закреплён на Flutter 3.41.4, проверяет lock-файлы, форматирование,
сгенерированные локализации, анализ и тесты. Production AAB и iPhone/iPad compile
проверяются отдельными release-задачами. Gradle wrapper хранится в Git, а JAR и дистрибутив
проверяются официальными SHA-256.

## Архитектура

- `lib/app` — композиция зависимостей, маршрутизация и глобальные providers;
- `lib/core` — API, авторизация, SQLite, синхронизация, аудио и дизайн-система;
- `lib/features` — независимые вертикальные продуктовые модули;
- `lib/l10n` — RU/EN/AR/TR, включая полноценный RTL;
- `test` — unit- и widget-тесты: модели, репозитории, офлайн-пакеты, экраны и раскладка
  при разных языках, темах и размере шрифта.

Детальные границы слоёв, offline-модель и порядок расширения описаны в
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Безопасность и приватность

- access/refresh token, installation ID и installation credential хранятся в
  Keystore/Keychain-backed secure storage;
- HTTP cleartext разрешён только для локального API в debug/local;
- API не следует HTTP redirect; profile/release принимают соответствующий окружению HTTPS origin;
- резервное копирование данных приложения отключено;
- координаты используются только для запроса расчёта времени намаза и не добавляются
  в аналитику;
- технические UUID пользователя и устройства не показываются в пользовательском UI.

## Ограничения тестовой версии

Android-сборка подписывается ключом загрузки и выходит через Google Play: внутреннее и закрытое
тестирование, рабочей версии пока нет (см. [docs/release/google-play.md](../../docs/release/google-play.md)).
iOS в App Store Connect ещё не загружался, push-доставка не включена. Подписанная сборка
собирается и загружается в TestFlight workflow `iOS release` (`.github/workflows/ios-release.yml`,
Release подписывается вручную); план выпуска и что нужно от владельца — в
[docs/release/app-store.md](../../docs/release/app-store.md). Книги и квизы
показаны как будущие разделы. Тексты переводов/тафсира не подменяются mock-данными:
интерфейс сообщает, когда утверждённый источник ещё не подключён.

Мобильный Мусхаф показывает опубликованные макеты из каталога API. Для локальной разработки
`make up` автоматически импортирует все 13 макетов Quran.Foundation.
Официальные шрифты и изображения слов загружаются непосредственно при чтении. Быстрый переход покрывает суру/аят, страницу, джуз, хизб
и руб аль-хизб. Текстовая читалка сохраняет размер арабского текста, межстрочный и межаятный
интервалы и режим без отвлечений; эти настройки не меняют геометрию готовых страниц. Полный
Мусхаф адаптирован и для альбомной ориентации: страница сохраняет исходные пропорции,
симметрично скрывает только внешние боковые поля страницы, заполняет ширину экрана и
просматривается по вертикали; горизонтальный жест по-прежнему перелистывает страницы.
При каждом повороте трансформация страницы сбрасывается к канонической компоновке новой
ориентации, поэтому альбомное смещение или масштаб не могут увести портретную страницу за
границы экрана. На телефоне в альбомной ориентации кнопка воспроизведения стоит в нижнем ряду
панели, а не над ним, чтобы панели закрывали меньше страницы. Кнопка-луна в верхней панели
включает ночной Мусхаф: тёмная бумага и светлые чернила, цвета таджвида и выделений сохраняют
оттенок (`mushafNightFilter` в `mushaf_paper.dart` — один цветовой фильтр для страниц-шрифтов и
страниц-картинок); выбор хранится в настройках устройства (`mushaf_night`). Полный
плеер уже переключает вид чтения и чтеца с сохранением текущей суры и безопасным переносом
позиции по совместимым таймкодам, а также качество аудиопотока без потери позиции. Мобильный
План использует общий с web server-authoritative goal, ручные и автоматические reading
sessions, историю, серии и prayer check-ins; при отсутствии сети последний dashboard остаётся
доступен только для просмотра. Автоматический зачёт учитывает активное время и только
последовательное продвижение, не превращая быстрый переход по Мусхафу в ложный прогресс;
неотправленная сессия повторно доставляется с тем же idempotency ID. Далее идёт
release/performance hardening. Оптимизация растровых публикаций изолирует часто обновляемый таймлайн от
статичной части развёрнутого плеера, объединяет одновременные запросы одной страницы и
не пересчитывает её SHA-256 при каждом возврате, пока размер и системные timestamps файла не
изменились. Кэш проверок ограничен двенадцатью ближайшими файлами; первая проверка и любое
изменение файла по-прежнему проходят полную проверку WebP, размера и checksum.
Глобальная оболочка, Home, каталог чтецов и мини-плеер подписаны только на смысловое состояние
аудио и не перестраиваются на каждом обновлении позиции. Непрерывный position tick локализован
в transport-панели развёрнутого плеера и активной аудиокарточке Du’a.
Если один чтец опубликован отдельными backend-записями для разных видов чтения, приложение
сохраняет выбранный recitation/reciter ID, но разрешает портрет через объединённый профиль
человека. Поэтому каталог, Мусхаф, мини-плеер, полный плеер и новая системная media-карточка
используют один avatar URL.
Нижняя панель воспроизведения в полноэкранном Мусхафе — тот же `IqroMiniPlayer`, что и
над основной навигацией: отдельной расходящейся реализации для читалки больше нет.

Мини-плеер над навигацией сворачивается свайпом по полоске в любую сторону: она собирается в
круглую кнопку 60 dp в углу. Касание кнопки разворачивает полоску обратно, касание самой полоски
по-прежнему открывает полный плеер. Отдельной кнопки сворачивания нет; экранный диктор получает
действие «Свернуть» (`CustomSemanticsAction`). Свайп засчитывается от 32 dp или быстрым движением
от 16 dp со скоростью от 500 dp/с, те же пороги у сайта (`services/web/lib/mini-player.ts`). На
сайте скрытая кнопка «Свернуть панель плеера» осталась для экранных дикторов и клавиатуры и
видна, только пока на ней фокус. Плеер в полноэкранном Мусхафе тоже сворачивается смахиванием
в круглую кнопку, звук при этом продолжает играть.

При открытии приложения и сайта полоска свёрнута в кнопку (`miniPlayerCollapsedProvider`; на
сайте `INITIAL_MINI_PLAYER_STATE`). Развёрнутая полоска сворачивается, когда открывается другая вкладка (`AppShell`); на сайте —
когда открывается другая страница (`route-change` в `lib/mini-player.ts`).

Пока человек ни разу не свернул полоску сам, она показывает, как это делается
(`MiniPlayerHint`): свёрнутая разворачивается, через 1,6 с сдвигается вбок к своему углу, как
от свайпа, и сворачивается; развёрнутая сдвигается, сворачивается и через 1,6 с разворачивается
обратно. Подсказка запускается на главной через 2,5 с после открытия приложения, возвращения в
него или перехода на главную, не чаще раза в 6 часов и не больше пяти раз (`miniPlayerHintDue`;
на сайте `playerHintDue`, ключ `iqro_player_hint_v2`, только при идущем воспроизведении). Любое
действие человека в это время её прерывает, с «уменьшением движения» её нет. Позже её заменит
подробный онбординг, см. [`docs/in-app-tour-plan.md`](../../docs/in-app-tour-plan.md).
Короткое касание выделяет аят, сохраняет место чтения и показывает компактные плавающие
панели. Повторное касание того же аята или свободного поля скрывает/показывает меню.
В нижней панели показаны семь точек соседних страниц, справа налево. Каждая точка
соответствует конкретной странице; касание или движение пальцем переключает страницу,
не закрывая панель. Во время жеста набор точек фиксирован, после отпускания снова
центрируется вокруг выбранной страницы. Короткий `selectionClick` выполняется ровно
при фактической смене страницы (включая обычное перелистывание), но не при касании
текущей точки или достижении границ выбранного макета (548/604/610).
Android-отклик уточнён: вместо OEM `CLOCK_TICK` используется короткий 22-мс one-shot
через `MainActivity : AudioServiceActivity`, с ограничением частоты и проверкой
системной настройки касаний. В «Настройках» есть отдельный выключатель вибрации
перелистывания; старые настройки мигрируют со значением «включено». iOS использует
стандартный лёгкий impact. Отсутствие вибромотора не блокирует чтение. Новая launcher
activity — `forum.iqro.app/.MainActivity`; старое прямое имя AudioServiceActivity
не используйте в командах запуска. Изменение activity требует переустановки APK поверх,

Круглая кнопка читает открытую страницу голосом чтеца Мусхафа: от выделенного аята (или от

звук не запускает. Удержание слова 0,3 секунды выделяет слово, меню не открывается; меню аята
открывается касанием номера аята или кнопкой справа внизу. Запрос аудио, ожидающий данные,
отбрасывается при выборе другого аята, страницы или аккаунта.
Перелистывание, прокрутка в альбомном режиме и pinch-to-zoom не открывают подробности.
Подробности показывают фрагменты выбранного Мусхафа: начертание, огласовки и маркеры
остаются такими же, как на странице. Если аят занимает несколько страниц, используются
все его страницы по индексу выбранного макета. Разные версии данных не смешиваются.
Для QF фрагменты рисуются теми же словами и ресурсами; при ошибке доступна повторная загрузка.
Следующие особенности относятся только к необязательным растровым публикациям:
если растровый фрагмент недоступен, показывается канонический текст с пометкой «Текст».
Когда огласовки соседних строк перекрываются и отдельный фрагмент нельзя безопасно
вырезать, показывается неизменённое изображение с выделенным аятом в прокручиваемом окне
«Мусхаф»: исходное начертание сохраняется вместе с контекстом соседних аятов.
FileImage использует общий кэш декодированной страницы, без отдельного пакета шрифтов.
На обычных портретных страницах свободная высота распределяется только между строками
с проверенными пустыми полосами самого растра: границы hit map могут проходить через
огласовки и сами по себе не дают права разрезать изображение. Анализ пикселей выполняется один
раз вне UI isolate, результаты кэшируются для ближайших шести изображений без хранения
дополнительных пиксельных буферов. Пока безопасные полосы не найдены или их меньше восьми,
страница остаётся цельной; пропорции букв не меняются. Заголовки и орнаментальные
первые две страницы не разрезаются. Подсветка и hit testing используют ту же геометрию,
пустые промежутки не выбирают соседний аят. Регионы одного аята на разных строках
объединяются в один контур, поэтому заливка и обводка не дают шва между строками. Фон — единая светлая бумага, сверху остаются
названия суры/джуза, снизу — номер страницы. Альбомная прокрутка сохраняется.
Прозрачность панели сохраняется обычной композицией цвета и рамки без постоянного
`BackdropFilter`: перелистывание страниц не заставляет GPU заново размывать лежащий под
плеером фрагмент Мусхафа. При быстром перелистывании сохранения позиции выполняются строго
последовательно, а из промежуточной очереди остаётся только самая свежая страница; выбранный
аят записывается через ту же последовательную очередь, чтобы поздняя запись предыдущей
страницы не затёрла последнее касание.

Мобильные настройки намаза используют тот же revisioned профиль, что и web: поддержаны
стандартный и ханафитский расчёт Асра, ручные поправки шести времён и допустимые выбранным
методом правила высоких широт/полярного круга. Изменения сразу применяются локально,
перепланируют уведомления и при отсутствии сети ожидают безопасной синхронизации.
Если точная геолокация недоступна, пользователь может найти город поиском по базе на сервере
(`/prayer/cities`) или выбрать из встроенного списка; у каждого города проверенная IANA
timezone. От тех же координат приложение показывает направление Киблы.
В шторке Киблы работает живой компас (`lib/features/prayer/qibla_compass.dart`): на iOS —
`trueHeading` CoreLocation, на Android — rotation vector с поправкой магнитного склонения по
WMM2025 (пакет `geomag`). Датчики включены только пока шторка открыта и приложение на экране;
при низкой точности показывается подсказка калибровки «восьмёркой», при наведении на Киблу
(≤ 3°) — подсветка и вибрация. Без компаса остаётся географический азимут от севера.

План напоминаний (несколько сотен будильников Android на месяц вперёд) приложение ставит заново
при запуске и при каждом возвращении на экран, но через 8 секунд, после анимации главной
(`IqroApp._reminderRenewalDelay`). Плагин уведомлений выполняет каждый вызов на главном потоке
Android и переписывает весь список; пока он работает, кадры опаздывают, и на Redmi Note 7 главная
шла рывками, 10 кадров в секунду вместо 60. Первая загрузка правил (`ReminderController`) план
не переставляет: это делает отложенный шаг. После принудительной остановки Android снимает все
будильники, и они возвращаются через ~8 секунд после запуска.

Напоминание со звуком точно во время намаза (без сдвига) играет короткий азан: Мекки
(по умолчанию, ~14 с) или Медины (~20 с); выбор «Обычный» оставляет системный звук. Выбор
делается на экране «Напоминания» и хранится в настройках устройства (`reminderAdhan`).
Файлы: `android/app/src/main/res/raw/adhan_*.mp3` и `ios/Runner/adhan_*.caf` (iOS играет не
дольше 30 с). На Android звук канала фиксируется при его создании, поэтому у каждого азана
свой канал `iqro_reminders_adhan_<makkah|madinah>`.

Звук может быть выключен настройкой, которую приложение не видит напрямую: так, Xiaomi
(MIUI) по умолчанию выключает «Разрешить звуки» у приложений вне заводского списка, и
напоминание только вибрирует. Поэтому на Android `NotificationSoundCheck.kt` проверяет
результат, а не марку телефона: публикует беззвучное уведомление
(`res/raw/sound_check.mp3`, канал `iqro_sound_probe`, удаляется после проверки) и ждёт, начнёт
ли система проигрывать звук уведомления. Запрет уведомлений или заглушённый канал азана —
«звука нет»; беззвучный режим, вибрация или «Не беспокоить» — «звук есть» (ложная тревога хуже
пропущенной). На iOS читается настройка звука уведомлений. Если звука нет, онбординг после
шага напоминаний показывает шаг «Звук азана» с предупреждением и тумблером, открывающим
настройки уведомлений приложения; после возврата состояние читается заново. Тем, кто
установил приложение раньше, то же предупреждение один раз показывает окно при запуске
(`lib/features/reminders/reminder_sound_dialog.dart`): только если напоминания о намазе со
звуком включены, после привязки аккаунта; результат запоминается (`reminderSoundChecked`).
Решение системы об уведомлении видно в `adb shell logcat -b events -d | grep notification_alert`
(`[key,buzz,beep,blink]`, `beep=0` — звук не запускался).

Месячный календарь рассчитывает каждый гражданский день тем же pinned local engine и теми же
пользовательскими настройками; после получения метода и location он доступен без сети.
Нативный средний виджет времени намаза реализован отдельно для Android (Glance с RemoteViews)
и iOS/iPadOS (WidgetKit), но получает один и тот же восьмидневный timeline из Flutter local
prayer engine. На тёмной карточке крупно показаны часы и минуты ближайшего намаза, его название
и системный обратный отсчёт; рядом — пять молитв и восход. Восход не становится отдельной
обязательной молитвой в переключении следующего намаза. RU/EN/AR/TR следуют языку IQRO,
арабская компоновка зеркальная, время сохраняет направление слева направо. Минимальный
размер Android — 250 × 110 dp; iOS использует systemMedium.

Виджет переключается по сохранённым абсолютным моментам, обновляется после смены
location/метода/поправок/языка и при запуске или возврате в приложение. Системный таймер не
требует ежесекундного запуска Flutter; своевременное переключение зависит от планировщика ОС.
Тап открывает экран намаза. Android может запросить добавление прямо из IQRO;
на iOS система требует ручного добавления через галерею.

страниц/минут/аятов и пять строк чтения после намаза. Он получает локализованный snapshot
из `PlanWidgetService` после загрузки/изменения плана, смены языка и возврата в приложение.
Прогресс истекает в полночь часового пояса плана, и виджет сам начинает следующий день без
запуска приложения: snapshot несёт блок `nextDay` (та же цель, прочитано 0, строки после
намаза по нулям, та же стадия пальмы). Android переключается по будильнику на `validUntil`,
который заново ставится при каждой отрисовке виджета (после перезагрузки, обновления, force
stop); iOS кладёт отдельную запись timeline на тот же момент. Приложение заменяет этот день
настоящими данными при следующем запуске или возврате. Пока данных нет (новая установка, выход
из аккаунта), и до первой отрисовки на Android виджет показывает текст «Откройте план в IQRO,
и здесь появится цель на день», а не пустую карточку или индикатор загрузки Glance.
При смене аккаунта snapshot очищается. Карточка «Сегодня» на главной сайта так же сама
перезагружается, если вкладка осталась открытой после полуночи. Нажатие на основную карточку открывает
вкладку «План», на правый блок — «После намаза». Добавить его можно кнопкой виджета в шапке
раздела «План» или через системную галерею. На iOS оба виджета входят в одно расширение.
Android-разметка: `res/layout/reading_plan_widget.xml`; Swift-шаблон:
`home_widget/native/reading_plan_view.swift`. Общая маршрутизация проверяет только известные
ссылки виджетов; выбранная вкладка синхронизируется с адресом для повторных нажатий.

Для подписанной iOS-сборки App Group `group.forum.iqro.app` должен быть зарегистрирован в
Apple Developer и включён в provisioning profiles приложения и WidgetKit extension.

Подробный порядок подписанной публикации описан в
[`docs/RELEASE.md`](docs/RELEASE.md).

### Логотип и заставка запуска

Внутри приложения используется `assets/brand/iqro-logo.png`; Android и iOS имеют
отдельные ресурсы значка с той же восковой печатью. Для обновления значка на
телефоне требуется установка новой сборки.

Фоновый плеер и напоминания используют одноцветную надпись IQRO для системного
маленького значка Android. В напоминаниях большой значок — полноцветная печать;
плеер показывает портрет чтеца, а при его отсутствии — локальную печать IQRO,
доступную без сети. Производные ресурсы сайта, плеера и уведомлений обновляются
командой `python3 tool/generate_brand_surfaces.py` (требуется Pillow).

`assets/brand/startup.mp4` воспроизводится локально без звука только при первом запуске
после установки; следующие запуски открываются сразу, как только готовы зависимости. Ролик
заполняет весь экран (лишнее по краям обрезается); системные панели скрыты на время показа.
Пока приложение запускается, системный splash Android и iOS и экран загрузки Flutter
показывают восковую печать IQRO (PR #34). Подготовка приложения идёт одновременно с роликом. После завершения
обоих этапов открывается основной экран; при медленной подготовке остаётся экран
загрузки. Системное отключение анимации пропускает ролик. Ошибка декодера или
тайм-аут заставки не блокирует запуск, а ошибка подготовки позволяет повторить
попытку без повторного показа видео.

## Проверка чтения вслух

На экране чистого арабского текста (свайп вправо из чтения) есть кнопка микрофона. Она включает
распознавание речи телефона (`speech_to_text`, арабский язык), и круглая лупа идёт по словам,
которые читатель произносит. Только приложение: на сайте функции нет — это решение владельца.

Код: `lib/features/quran/recitation_match.dart` (сопоставление),
`lib/features/quran/recitation_follow.dart` (слушатель, лупа, подсказка),
`lib/features/quran/reader_flow_screen.dart` (экран). Тесты:
`test/features/recitation_match_test.dart` и «the microphone puts a lens…» в
`test/features/reader_swipe_widget_test.dart`.

### Кто слушает

- **Android — модель в телефоне** (`lib/features/quran/recitation_model/`). Звук с микрофона
  (`RecitationMic.kt`, 16 кГц) идёт в модель `Hisnlabs/tajweed-v2` (`assets/recitation_model/`, исполняет
  ONNX Runtime), и по её вероятностям звуков приложение находит, до какого места текста дошёл голос
  (`follow_core.dart`). Звук никуда не передаётся, интернет не нужен.
- **Запасной способ — распознавание речи телефона** (`recitation_follow.dart`, `speech_to_text`): на iOS
  всегда; на Android — если модель не загрузилась или число слов аята в таблице ожидаемых звуков не совпало
  с текстом на экране. Переход происходит сам, без участия читателя. Сейчас таблица совпадает во всех
  6236 аятах (`test/features/recitation_model_table_test.dart`), сур на запасном способе нет.

Разделы «Правила самопроверки», «Чего функция не умеет», «Распознавание и данные» и «Задержка» ниже
описывают запасной способ; отличия модели — в разделе «Модель в телефоне».

### Модель в телефоне

- **Лупа** встаёт на слово, когда оно начато (два первых звука), а не после его конца: на Redmi Note 7
  в среднем через 0,6 с от начала слова. Правила те же: только следующее слово; нажатие на слово ставит
  место; назад — два слова подряд из пройденного; повтор последнего слова не ошибка; сказанное до первого
  слова («а‘узу», басмала) не считается.
- **Красная лупа и вибрация**: слово пропущено или сказано другое; в слове другая буква или огласовка
  (модель уверенно слышит другой звук на месте написанного) либо больше одного несовпавшего звука; гунна
  на نّ / مّ почти пропущена (один счёт из четырёх и меньше); мадд муттасыль вдвое короче. Длинное первое
  слово тоже (например «Алиф Лям Ро» вместо «Алиф Лям Мим»). В чём ошибка, приложение не пишет; после
  верного повтора слова лупа идёт дальше. Последняя огласовка слова, не сказанная при остановке, не ошибка.
- **Не останавливает**: ихфа, мадд лязим (модель в них ошибается сама), гунна, укороченная наполовину,
  мадд, который допустимо читать коротко, калькаля, тафхим.
- **Память и нагрузка**: модель живёт в отдельном изоляте от включения микрофона до выключения или ухода
  с экрана; при выключении изолят сам освобождает память модели (`RecitationModelSession.close`). Пока
  микрофон включён, заняты около четырёх ядер из восьми (Redmi Note 7).
- **Размер**: модель 23 МБ, таблица 2 МБ, библиотека ONNX Runtime 36 МБ для arm64 (только ABI, под которые
  собирается Flutter: `abiFilters` в `android/app/build.gradle.kts`).
- **Замеры и история решений** — `docs/recitation-on-device-spike/README.md`. Стенд на компьютере тем же
  кодом: `tool/recitation_model/harness.dart`; таблицу пересобирает `tool/recitation_model/build_table.py`.
- **Чего нет**: iOS (там запасной способ, а файлы модели пока тоже попадают в сборку); подсказок, в чём
  именно ошибка.

### Что видит читатель

- Перед первым включением — предупреждение (один раз, `recitation_notice_seen`). На Android: голос
  слушает программа в телефоне, звук никуда не передаётся; если она не запустится — служба Google.
  На iOS: голос распознаёт служба Apple, на старых телефонах через интернет. IQRO запись не хранит
  и на свой сервер не отправляет.
  Пока читатель не включал микрофон, у кнопки время от времени всплывает подсказка.
- Под текстом — строка: «Слушаю…», последние услышанные слова, «Не слышу…» (8 с без слов при
  включённом микрофоне) или причина: нет связи со службой, служба не знает арабский,
  распознавание недоступно.
- Если на телефоне нет службы распознавания или микрофон не разрешён, вместо включения
  показывается сообщение.

### Правила самопроверки

- Лупа переходит только на следующее ожидаемое слово. Слова из следующих строк её туда не
  переносят, пропущенное слово не перешагивается.
- Сравнение — по буквам без огласовок и знаков, с едиными формами алифа, хамзы и та-марбуты;
  допуск — одна буква в словах до 6 букв, две в более длинных (в Мусхафе нет алифов, которые
  пишет распознаватель). Слово, которое распознаватель записал двумя, считается одним.
- Ошибка — когда вместо ожидаемого слова услышано другое или оно пропущено. Чтобы ослышки
  распознавателя не останавливали на каждом шагу: два несовпавших слова подряд — ошибка сразу;
  одно несовпавшее слово — ошибка, только если за 1,5 с следующие слова его не исправили
  (распознаватель переписывает последние слова фразы). Лишнее слово между верными ошибкой
  не считается. До первого верно прочитанного слова не считаются слова «а‘узу» и басмалы.
- При ошибке лупа становится красной и стоит на слове, которое нужно прочитать; телефон
  коротко вибрирует один раз (если в настройках чтения включена вибрация). После верного
  прочтения этого слова лупа снова золотая и идёт дальше.
- Последнее слово можно повторить. Вернуться назад голосом — прочитать два слова подряд из
  уже пройденного. Начать с другого места — нажать на слово при включённом микрофоне.

### Чего функция не умеет

Огласовки и таджвид. Распознаватель отдаёт слова без огласовок и подгоняет услышанное под
известное ему слово, поэтому неверный харакат или долгота ошибкой не станут.

### Распознавание и данные

- Распознавание на самом телефоне запрашивается там, где система это умеет (iOS, Android 12+);
  если модели арабского нет, первое прослушивание даёт ошибку и дальше идёт сеть. На Android
  10–11 выбирает сама система, на проверочном Redmi (Android 10) это сеть.
- Звук идёт от телефона в службу распознавания напрямую; сервер IQRO в этом не участвует и
  новых запросов не получает. Распознанные слова не сохраняются и в журнал телефона не пишутся
  (журнал `IQRO recitation …` есть только в отладочной сборке).
- Разрешения: Android — `RECORD_AUDIO` и запрос службы `android.speech.RecognitionService` в
  манифесте; iOS — `NSMicrophoneUsageDescription` и `NSSpeechRecognitionUsageDescription`
  (`Info.plist` и `*.lproj/InfoPlist.strings` на четырёх языках).
- Политика конфиденциальности: раздел 13 в `services/web/lib/legal-content.ts`.

### Задержка

Замер на Redmi Note 7 (Android 10, распознавание Google через сеть; слова проигрывались с
компьютера, отметки — по журналу телефона в отладочном выводе):

| | значение |
|---|---|
| конец слова → телефон сообщил слово, чтение подряд | ≈0,6 с |
| то же для слова перед паузой | ≈0,8–0,9 с |
| слово сообщено → лупа на месте | ≈0,08 с (тот же кадр + переход 60 мс) |

Основная задержка — ответ распознавателя; приложение на неё не влияет. Первые слова после
включения микрофона могут прийти пачкой через несколько секунд (в замере — через 8 с):
распознаватель ещё устанавливает соединение. Изредка он на 20–35 с перестаёт отдавать слова при
включённом микрофоне; лупа в это время стоит, а под текстом появляется «Не слышу…».

Размер шрифта на этом экране меняется двумя пальцами, двойной тап возвращает размер по
умолчанию.
