# IQRO Mobile

Нативный мобильный клиент IQRO на Flutter для Android, iPhone и iPad. Все платформы
используют один Dart-код и действующие API-контракты платформы, хранят пользовательские
изменения локально и синхронизируют их после восстановления сети.

## Быстрый запуск на Android

Заполните ключи в backend `.env` по [корневой инструкции](../../README.md).
`make mobile-run` автоматически запускает backend, применяет миграции и подготавливает
Коран, ду’а, переводы, тафсиры, аудио и мобильные страницы, затем запускает Flutter.

Нужны Flutter 3.41.4 (версия CI), Android SDK и эмулятор либо устройство с USB-отладкой.

```bash
# Из корня репозитория; backend и данные готовятся автоматически:
make mobile-run
```

Debug по умолчанию использует `APP_ENV=local`: Android — `http://10.0.2.2:8000`,
iOS Simulator — `http://127.0.0.1:8000`. Для физического телефона укажите IP компьютера:

```bash
make mobile-run MOBILE_ARGS="--dart-define=API_BASE_URL=http://192.168.1.20:8000"
```

Замените IP своим и добавьте его в `DJANGO_ALLOWED_HOSTS` backend `.env`, затем выполните
`make dev-up`. Телефон и компьютер должны находиться в одной сети.
На Android по USB можно использовать `adb reverse tcp:8000 tcp:8000` и
`API_BASE_URL=http://127.0.0.1:8000`.

HTTP разрешён только для local/debug и локальных адресов. Profile/release сохраняют
требование HTTPS и явного окружения. Медиа с относительными URL загружаются с того же
адреса backend. Ключи Quran.Foundation не передаются в Flutter.

В разделе «Аудио» карточка с круглым аватаром является основной кнопкой запуска:
тап выбирает доступный вариант чтения, продолжает текущую суру (либо открывает
Аль-Фатиху), запускает воспроизведение и сразу показывает полный плеер. Над сеткой
работает фильтр по виду чтения; по умолчанию выбран «Мурратталь», а недоступные в
каталоге виды не показываются. Несколько стилей одного чтеца остаются одной персоной
в соответствующих фильтрах, поэтому дубли аватаров внутри одного вида не создаются.
Развёрнутый плеер показывает фактический битрейт и позволяет выбрать только опубликованные
для текущего трека варианты `economy`, `standard` или `high`. Выбор хранится на устройстве;
если нужного варианта нет у другой записи, используется назначенный бэкендом default без
ошибки воспроизведения.

В «Настройки → Офлайн-хранилище» перечислены все полные и частично загруженные пакеты,
их фактический размер на устройстве, заявленный полный размер и состояние. До начала загрузки
размер берётся из проверенного manifest и показывается в отдельном подтверждении. Общий лимит
приложения — 3 ГБ; автоматического удаления нет, каждый конкретный пакет удаляется только после
подтверждения. Активная офлайн-запись сначала корректно останавливает плеер.

## Чёткость и поворот Мусхафа

Читалка отображает все 13 макетов Quran.Foundation (548, 604 или 610 страниц).
Для шрифтовых макетов Flutter загружает официальный TTF, включая COLRv1 таджвид;
для трёх графических макетов — PNG отдельных слов. Строки масштабируются равномерно
без изменения пропорций букв. Те же границы используются для подсветки и нажатий.
Альбомный режим сохраняет пропорции каллиграфии и допускает вертикальную прокрутку.

Каталог, индекс аятов и страницы получает локальный API. При пустом каталоге приложение
показывает отсутствие данных; для подготовки достаточно `make up` в корне репозитория.
Смена макета сохраняет ссылку на аят, а номер страницы определяется по его индексу.
Закладки и прогресс остаются в каноническом корпусе.

Открытые страницы, индекс и ресурсы сохраняются на устройстве: файлы проверяются SHA-256,
запросы одного ресурса объединяются, версии данных не смешиваются. Первое открытие
требует сети. Массовая загрузка полного офлайн-пакета для новых 13 макетов пока не
предусмотрена; интерфейс объясняет кеширование по мере чтения. Ранее опубликованные
растровые наборы сохраняют прежние проверки WebP и установку полного офлайн-пакета.
[Каталог макетов и проверка](../../docs/quran-foundation-mushafs.md).

## Тестовый APK

```bash
flutter build apk --debug \
  --dart-define=API_BASE_URL=https://staging.iqro.forum \
  --dart-define=APP_ENV=staging

adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

- application ID: `forum.iqro.app`;
- минимальная версия Android определяется поддерживаемой версией Flutter;
- local используется по умолчанию только в debug-режиме;
- release-сборка без явных `APP_ENV` и `API_BASE_URL` намеренно не завершит
  инициализацию, а production принимает только `https://iqro.forum`;
- `APP_DOWNLOAD_URL` задаёт встроенную запасную ссылку для функции «Поделиться».

Debug APK подписывается стандартным отладочным ключом. Release-сборка не использует
debug-подпись: CI или локальный защищённый контур должен передать `android/key.properties`
и keystore. Секреты не должны попадать в Git.

## iPhone и iPad

Требуются полный Xcode 26+, Ruby 3.2+ (в CI — 4.0.1) и Bundler 4.0.3.
CocoaPods 1.17.0 и его зависимости закреплены в `Gemfile.lock`; команды `make mobile-ios-*`
устанавливают их в `vendor/bundle` и запускают через `bundle exec`.
Apple Developer signing нужен только для установки на физическое устройство или публикации.
Если используется Homebrew Ruby, сначала добавьте его в `PATH`:

```bash
brew install ruby
export PATH="$(brew --prefix ruby)/bin:$PATH"
gem install bundler -v 4.0.3
# Из корня репозитория: backend и данные также готовятся автоматически.
make mobile-ios-run
```

Проверить конфигурацию и собрать локальный debug target отдельно:

```bash
make mobile-ios-config-check
cd clients/iqro_mobile && bundle exec flutter build ios --debug --no-codesign --dart-define=APP_ENV=local
```

iOS target имеет bundle ID `forum.iqro.app`, поддерживает iOS/iPadOS 14+, UIScene,
фоновое аудио, локальные уведомления и локализованные permission-тексты RU/EN/AR/TR.
Геопозиция запрашивается только во время использования приложения для расчёта времени
намаза; фоновый location-доступ не включён.

Аккаунт-зависимое обслуживание (sync, auth refresh и перепланирование уведомлений)
выполняется при запуске и каждом возврате приложения на передний план. Headless-задача
Workmanager пока намеренно не меняет аккаунтные данные: отдельный Dart isolate нельзя
безопасно согласовать с одновременным logout/handoff без межпроцессного durable fence.
Уже поставленные системные уведомления продолжают работать без открытого приложения;
на iOS горизонт плана ограничен 8 днями и продлевается при следующем открытии/возврате.

Фирменные app icon и launch mark для обеих платформ воспроизводимо экспортируются из
одной геометрии командой `cd clients/iqro_mobile && swift tool/generate_app_icons.swift`.

## Окружения без flavors

Отдельные flavors не нужны: один и тот же код компилируется с явной конфигурацией.

```bash
# Тестовый сервер
make mobile-android-staging

# Production AAB; без keystore получится только неподписанный compile-check
make mobile-android-production

# Production iOS compile-check; без signing и загрузки в App Store Connect
make mobile-ios-production
```

`APP_ENV=staging` принимает только `https://staging.iqro.forum`, а
`APP_ENV=production` — только `https://iqro.forum`. Это исключает случайный релиз,
направленный не в то окружение.

## Проверки

```bash
make mobile-check
make mobile-android-staging
```

Mobile CI закреплён на Flutter 3.41.4, проверяет lock-файлы, форматирование,
сгенерированные локализации, анализ, тесты, staging APK, production AAB и production
iPhone/iPad compile на Xcode 26.3. Gradle wrapper хранится в Git, а JAR и дистрибутив
проверяются официальными SHA-256.

## Архитектура

- `lib/app` — композиция зависимостей, маршрутизация и глобальные providers;
- `lib/core` — API, авторизация, SQLite, синхронизация, аудио и дизайн-система;
- `lib/features` — независимые вертикальные продуктовые модули;
- `lib/l10n` — RU/EN/AR/TR, включая полноценный RTL;
- `test` — unit-тесты модели сессии, настроек и API-моделей.

Детальные границы слоёв, offline-модель и порядок расширения описаны в
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Безопасность и приватность

- access/refresh token, installation ID и installation credential хранятся в
  Keystore/Keychain-backed secure storage;
- HTTP cleartext разрешён только для локального API в debug/local;
- API не следует HTTP redirect; profile/release принимают соответствующий окружению HTTPS origin;
- резервное копирование данных приложения отключено;
- координаты используются только для запроса расчёта времени намаза и не добавляются
  в аналитику;
- технические UUID пользователя и устройства не показываются в пользовательском UI.

## Ограничения тестовой версии

Store-signing, Play Console, App Store Connect и push-доставка намеренно не включены.
Production endpoint поддержан через compile-time конфигурацию, но публикация требует
Android upload keystore либо Apple certificates/provisioning profiles. Книги и квизы
показаны как будущие разделы. Тексты переводов/тафсира не подменяются mock-данными:
интерфейс сообщает, когда утверждённый источник ещё не подключён.

Мобильный Мусхаф показывает опубликованные макеты из каталога API. Для локальной разработки
`make up` автоматически импортирует все 13 макетов Quran.Foundation.
Официальные шрифты и изображения слов загружаются непосредственно при чтении. Быстрый переход покрывает суру/аят, страницу, джуз, хизб
и руб аль-хизб. Текстовая читалка сохраняет размер арабского текста, межстрочный и межаятный
интервалы и режим без отвлечений; эти настройки не меняют геометрию готовых страниц. Полный
Мусхаф адаптирован и для альбомной ориентации: страница сохраняет исходные пропорции,
симметрично скрывает только внешние боковые поля страницы, заполняет ширину экрана и
просматривается по вертикали; горизонтальный жест по-прежнему перелистывает страницы.
При каждом повороте трансформация страницы сбрасывается к канонической компоновке новой
ориентации, поэтому альбомное смещение или масштаб не могут увести портретную страницу за
границы экрана. Полный
плеер уже переключает вид чтения и чтеца с сохранением текущей суры и безопасным переносом
позиции по совместимым таймкодам, а также качество аудиопотока без потери позиции. Мобильный
План использует общий с web server-authoritative goal, ручные и автоматические reading
sessions, историю, серии и prayer check-ins; при отсутствии сети последний dashboard остаётся
доступен только для просмотра. Автоматический зачёт учитывает активное время и только
последовательное продвижение, не превращая быстрый переход по Мусхафу в ложный прогресс;
неотправленная сессия повторно доставляется с тем же idempotency ID. Далее идёт
release/performance hardening. Оптимизация растровых публикаций изолирует часто обновляемый таймлайн от
статичной части развёрнутого плеера, объединяет одновременные запросы одной страницы и
не пересчитывает её SHA-256 при каждом возврате, пока размер и системные timestamps файла не
изменились. Кэш проверок ограничен двенадцатью ближайшими файлами; первая проверка и любое
изменение файла по-прежнему проходят полную проверку WebP, размера и checksum.
Глобальная оболочка, Home, каталог чтецов и мини-плеер подписаны только на смысловое состояние
аудио и не перестраиваются на каждом обновлении позиции. Непрерывный position tick локализован
в transport-панели развёрнутого плеера и активной аудиокарточке Du’a.
Если один чтец опубликован отдельными backend-записями для разных видов чтения, приложение
сохраняет выбранный recitation/reciter ID, но разрешает портрет через объединённый профиль
человека. Поэтому каталог, Мусхаф, мини-плеер, полный плеер и новая системная media-карточка
используют один avatar URL.
Нижняя панель воспроизведения в полноэкранном Мусхафе — тот же `IqroMiniPlayer`, что и
над основной навигацией: отдельной расходящейся реализации для читалки больше нет.
Короткое касание выделяет аят, сохраняет место чтения и показывает компактные плавающие
панели. Повторное касание того же аята или свободного поля скрывает/показывает меню.
В нижней панели показаны семь точек соседних страниц, справа налево. Каждая точка
соответствует конкретной странице; касание или движение пальцем переключает страницу,
не закрывая панель. Во время жеста набор точек фиксирован, после отпускания снова
центрируется вокруг выбранной страницы. Короткий `selectionClick` выполняется ровно
при фактической смене страницы (включая обычное перелистывание), но не при касании
текущей точки или достижении границ выбранного макета (548/604/610).
Android-отклик уточнён: вместо OEM `CLOCK_TICK` используется короткий 22-мс one-shot
через `MainActivity : AudioServiceActivity`, с ограничением частоты и проверкой
системной настройки касаний. В «Настройках» есть отдельный выключатель вибрации
перелистывания; старые настройки мигрируют со значением «включено». iOS использует
стандартный лёгкий impact. Отсутствие вибромотора не блокирует чтение. Новая launcher
activity — `forum.iqro.app/.MainActivity`; старое прямое имя AudioServiceActivity
не используйте в командах запуска. Изменение activity требует переустановки APK поверх,
а не hot reload. Анализатор и 19 профильных тестов прошли; profile APK собран.
Круглая кнопка воспроизводит именно выделенный аят у выбранного чтеца и раскрывает общий
мини-плеер; само касание страницы звук не запускает. Удержание около 0,5 секунды открывает
подробности; удержание пустого поля ничего не выбирает. Запрос аудио, ожидающий данные,
отбрасывается при выборе другого аята, страницы или аккаунта.
Перелистывание, прокрутка в альбомном режиме и pinch-to-zoom не открывают подробности.
Подробности показывают фрагменты выбранного Мусхафа: начертание, огласовки и маркеры
остаются такими же, как на странице. Если аят занимает несколько страниц, используются
все его страницы по индексу выбранного макета. Разные версии данных не смешиваются.
Для QF фрагменты рисуются теми же словами и ресурсами; при ошибке доступна повторная загрузка.
Следующие особенности относятся только к необязательным растровым публикациям:
если растровый фрагмент недоступен, показывается канонический текст с пометкой «Текст».
Когда огласовки соседних строк перекрываются и отдельный фрагмент нельзя безопасно
вырезать, показывается неизменённое изображение с выделенным аятом в прокручиваемом окне
«Мусхаф»: исходное начертание сохраняется вместе с контекстом соседних аятов.
FileImage использует общий кэш декодированной страницы, без отдельного пакета шрифтов.
На обычных портретных страницах свободная высота распределяется только между строками
с проверенными пустыми полосами самого растра: границы hit map могут проходить через
огласовки и сами по себе не дают права разрезать изображение. Анализ пикселей выполняется один
раз вне UI isolate, результаты кэшируются для ближайших шести изображений без хранения
дополнительных пиксельных буферов. Пока безопасные полосы не найдены или их меньше восьми,
страница остаётся цельной; пропорции букв не меняются. Заголовки и орнаментальные
первые две страницы не разрезаются. Подсветка и hit testing используют ту же геометрию,
пустые промежутки не выбирают соседний аят. Фон — единая светлая бумага, сверху остаются
названия суры/джуза, снизу — номер страницы. Альбомная прокрутка сохраняется.
Прозрачность панели сохраняется обычной композицией цвета и рамки без постоянного
`BackdropFilter`: перелистывание страниц не заставляет GPU заново размывать лежащий под
плеером фрагмент Мусхафа. При быстром перелистывании сохранения позиции выполняются строго
последовательно, а из промежуточной очереди остаётся только самая свежая страница; выбранный
аят записывается через ту же последовательную очередь, чтобы поздняя запись предыдущей
страницы не затёрла последнее касание.

Мобильные настройки намаза используют тот же revisioned профиль, что и web: поддержаны
стандартный и ханафитский расчёт Асра, ручные поправки шести времён и допустимые выбранным
методом правила высоких широт/полярного круга. Изменения сразу применяются локально,
перепланируют уведомления и при отсутствии сети ожидают безопасной синхронизации.
Если точная геолокация недоступна, пользователь может выбрать локально сохранённый город с
проверенной IANA timezone; от тех же координат приложение показывает направление Киблы как
географический азимут и явно не выдаёт его за показание живого магнитного компаса.
Месячный календарь рассчитывает каждый гражданский день тем же pinned local engine и теми же
пользовательскими настройками; после получения метода и location он доступен без сети.
Нативный средний виджет времени намаза реализован отдельно для Android (Glance с RemoteViews)
и iOS/iPadOS (WidgetKit), но получает один и тот же восьмидневный timeline из Flutter local
prayer engine. На тёмной карточке крупно показаны часы и минуты ближайшего намаза, его название
и системный обратный отсчёт; рядом — пять молитв и восход. Восход не становится отдельной
обязательной молитвой в переключении следующего намаза. RU/EN/AR/TR следуют языку IQRO,
арабская компоновка зеркальная, время сохраняет направление слева направо. Минимальный
размер Android — 280 × 140 dp; iOS использует systemMedium.

Виджет переключается по сохранённым абсолютным моментам, обновляется после смены
location/метода/поправок/языка и при запуске или возврате в приложение. Системный таймер не
требует ежесекундного запуска Flutter; своевременное переключение зависит от планировщика ОС.
Тап открывает экран намаза. Android может запросить добавление прямо из IQRO;
на iOS система требует ручного добавления через галерею.

Контракт данных находится в `home_widget/prayer_times.dart`. Для регенерации из каталога
мобильного клиента используйте `dart run tool/generate_prayer_widget.dart`: команда генерирует
Dart/Swift/Kotlin и устанавливает нативные представления из `home_widget/native/`.
Прямой запуск генератора пакета перезапишет эти представления. Android-разметка и фоны
находятся в `android/app/src/main/res/layout/prayer_times_widget.xml` и `res/drawable/prayer_*.xml`.
Swift-шаблон находится в `home_widget/native/prayer_times_view.swift`.

Виджет «План чтения» использует тот же тёмный стиль: дневная цель, оставшееся количество
страниц/минут/аятов и пять строк чтения после намаза. Он получает локализованный snapshot
из `PlanWidgetService` после загрузки/изменения плана, смены языка и возврата в приложение.
Прогресс истекает в полночь часового пояса плана; устаревшие данные заменяются предложением
открыть план. При смене аккаунта snapshot очищается. Нажатие на основную карточку открывает
вкладку «План», на правый блок — «После намаза». Добавить его можно кнопкой виджета в шапке
раздела «План» или через системную галерею. На iOS оба виджета входят в одно расширение.
Android-разметка: `res/layout/reading_plan_widget.xml`; Swift-шаблон:
`home_widget/native/reading_plan_view.swift`. Общая маршрутизация проверяет только известные
ссылки виджетов; выбранная вкладка синхронизируется с адресом для повторных нажатий.

Apple Developer и включён в provisioning profiles приложения и WidgetKit extension.
