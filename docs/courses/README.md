# Тематические курсы: контракт

Общий контракт для бэкенда, сайта и приложения. Полный план и решения владельца: [plan.md](plan.md).
Здесь только то, о чём три стороны должны договориться заранее: адреса, формат ответов,
разметка конспекта, события обновления кэша, маршруты и ключи хранения.

Этап 1 — курсы с конспектами. Видео (этап 2) и викторина (этап 3) уже описаны в контракте,
чтобы клиенты не пришлось менять потом: на этапе 1 `video` всегда `null`, событий викторины ещё нет.

## Границы

- Новый Django-модуль `quran_backend.modules.courses` («Тематические курсы»). Викторина — отдельный
  модуль `quizzes` (этап 3). Модули `salah` и `tajweed` не меняются.
- «Обучение намазу» и «Таджвид» в API курсов не входят. Клиенты сами ставят их первыми двумя
  карточками каталога и открывают их прежние страницы.
- Зарезервированные slug курса: `salah`, `tajweed`, `quiz`, `courses`, `new`, `preview`, `events`.
- Курс виден на языке, только если у его опубликованного выпуска есть этот язык. Частичных переводов
  нет: курс либо полностью на языке, либо не виден на нём.

## API

Префикс `/api/v1/`, адреса без слеша на конце (как `tajweed/course_urls.py`).
Публичные ответы через `PublicReadOnlyViewMixin`: weak ETag, `304`,
`Cache-Control: public, max-age=300, stale-while-revalidate=86400`.

Параметр `language`: `ru`, `en`, `ar` или `tr`, по умолчанию `ru`. Другое значение даёт `400`
с `{"language": ["Поддерживаются: ar, en, ru, tr."]}`, как в `salah/api.py`.

### `GET /api/v1/courses?language=ru`

Видимые курсы, у которых есть выпуск на этом языке, по `position`, затем по названию.
Пример: [course-list.example.json](course-list.example.json).

| Поле | Тип | Смысл |
|---|---|---|
| `language` | string | Язык ответа |
| `courses[].slug` | string | Адрес курса |
| `courses[].version` | string | Номер опубликованного выпуска, строкой (`"1"`) |
| `courses[].title`, `summary`, `source` | string | Тексты на этом языке; `source` — «Автор и источники», может быть `""` |
| `courses[].cover` | object или `null` | `{url, thumb_url, width, height}`, WebP 16:9 |
| `courses[].lesson_count` | int | Число тем |
| `courses[].minutes` | int | Сумма `minutes` тем |
| `courses[].video_minutes` | int | Сумма длительностей видео, округлённая вверх; на этапе 1 `0` |
| `courses[].published_at` | string | ISO 8601 |

### `GET /api/v1/courses/{slug}?language=ru`

Документ опубликованного выпуска на этом языке. Пример: [course-document.example.json](course-document.example.json).
`404 {"detail": "Такого курса нет."}`, если курса нет, он скрыт или у выпуска нет этого языка.

- `schema_version`: `1`.
- `course`: `slug`, `version`, `language`, `languages` (все языки выпуска), `title`, `summary`, `source`,
  `cover`, `published_at`, `checksum_sha256` (документа на этом языке).
- `lessons[]` по порядку:
  - `slug` — адрес темы внутри курса; `number` — порядковый номер с 1;
  - `title`, `summary`, `minutes` (int);
  - `video` — `null` на этапе 1; с этапа 2: `{url, bytes, duration_ms, width, height, spoken_language, poster: {url, small_url, width, height}}`, где `spoken_language` — `""` для видео без речи;
  - `notes` — блоки конспекта (ниже);
  - `sources` — массив строк, по источнику на строку.

Клиенты обязаны игнорировать незнакомые поля. Новое обязательное поле или новый тип блока
поднимает `schema_version`; клиент, получивший больший `schema_version`, показывает «Обновите
приложение» вместо курса.

## Конспект: разметка автора и блоки

Автор пишет конспект простым текстом с пометками. Сервер разбирает его один раз при подготовке
выпуска (`core/editorial/markup.py`) и отдаёт готовые блоки. Сайт и приложение только рисуют блоки,
поэтому показывают одно и то же. HTML и ссылок в разметке нет; всё выводится как текст.

| Пометка автора | Блок |
|---|---|
| пустая строка | граница блоков |
| `## ` в начале строки | `heading` |
| строки `- ` подряд | `list`, `ordered: false` |
| строки `1. `, `2. ` … подряд | `list`, `ordered: true` (номера рисует клиент) |
| строки `> ` подряд | `quote`; последняя строка вида `> — Источник` становится `source` |
| строки `! ` подряд | `note` («Важно») |
| остальное | `paragraph`; одиночный перенос строки — новая строка внутри абзаца |
| `**текст**` | сегмент с `bold: true`; непарные `**` остаются текстом |

Форма блоков:

```text
Segment   = {"text": string, "bold"?: true, "lang"?: "ar"}
heading   = {"type": "heading",   "dir": D, "text": Segment[]}
paragraph = {"type": "paragraph", "dir": D, "lines": Segment[][]}
list      = {"type": "list",      "dir": D, "ordered": bool, "items": Segment[][]}
quote     = {"type": "quote",     "dir": D, "lines": Segment[][], "source": string | null}
note      = {"type": "note",      "dir": D, "lines": Segment[][]}
D         = "ltr" | "rtl"
```

- Заголовок — всегда одна строка. Строка с другой пометкой начинает новый блок и без пустой строки
  перед ней. Источник цитаты отделяется длинным тире и пробелом: `> — Коран, 2:183`.
- `dir` блока определяется по первому «сильному» символу его текста: арабская письменность даёт `rtl`.
- Отрезки арабской письменности (U+0600–U+06FF, U+0750–U+077F, U+08A0–U+08FF, U+FB50–U+FDFF,
  U+FE70–U+FEFF вместе с пробелами и знаками между арабскими словами) становятся отдельными
  сегментами с `lang: "ar"`. Клиент рисует их арабским шрифтом и изолирует направление:
  сайт — `<bdi lang="ar">` со шрифтом `--font-arabic`, приложение — Amiri Quran и U+2068…U+2069.
- Соседние сегменты с одинаковыми признаками склеиваются; пробелы по краям строк обрезаются.
- Разбор никогда не падает: неизвестная пометка остаётся обычным текстом.
- Лимиты на язык: конспект темы до 20 000 символов, источники до 2 000. Документ на язык до 2 МиБ.

Общие примеры «разметка → блоки» для тестов всех трёх сторон: [notes-markup.cases.json](notes-markup.cases.json).
Бэкенд проверяет по ним разбор, клиенты — что рисуют каждый тип блока, `dir` и `lang`.

## Обновление кэша сайта

Бэкенд после commit отправляет через `enqueue_content_revalidation`:

```json
{"type": "courses.course.changed", "action": "activated", "course": "ramadan", "version": "2"}
{"type": "quizzes.quiz.changed", "action": "withdrawn", "quiz": "ramadan-basics", "version": "1"}
```

`action`: `activated` (публикация, возврат на сайт, откат на прежний выпуск) или `withdrawn` (скрыт).
Сайт принимает оба типа строгим парсером в `lib/content-revalidation.ts` и обновляет:

- курс: теги `courses:catalog`, `courses:course:{slug}`, `quizzes:catalog`; пути `/[locale]/courses`,
  `/[locale]/courses/[course]`, `/[locale]/courses/[course]/[lesson]`;
- викторину: теги `quizzes:catalog`, `quizzes:quiz:{slug}`; пути `/[locale]/quiz`, `/[locale]/quiz/[quiz]`.

PR сайта с этими типами выкатывается **раньше** бэкенда: неизвестный тип получает `422`, а бэкенд
не повторяет ответы 4xx (`app/api/internal/content-revalidation/route.ts`, `core/tasks.py`).

## Маршруты и вход

| | Сайт | Приложение |
|---|---|---|
| Каталог | `/{locale}/courses` | `/courses` |
| Курс | `/{locale}/courses/{course}` | `/courses/:course` |
| Тема | `/{locale}/courses/{course}/{lesson}` | `/courses/:course/:lesson` |
| Вход | шапка: «Курсы» вместо «Обучение намазу» и «Таджвид»; подвал; «Ещё» на телефоне | плитка «Курсы» в «Ещё» |

Прямые входы в «Обучение намазу» и «Таджвид» остаются в подвале сайта и на экране «Намаз», а в «Ещё»
на телефоне и в приложении их заменяет «Курсы».
Пункт «Викторина» появляется в навигации только на этапе 3, вместе с самим разделом.
Пять нижних вкладок приложения не меняются.

## Прогресс на устройстве

Решение 5: на старте прогресс хранится только на устройстве. Формат совпадает с
`lib/course-progress.ts`, чтобы синхронизация с аккаунтом потом включилась без переделки.

- Сайт, `localStorage`: `courses.progress.<slug>` = `{"lessons": {"<lesson>": {"status": "completed", "step_slug": "", "content_version": "<version>", "updated_at": "<ISO>"}}}`.
  `status` — `"in_progress"` (тема открыта) или `"completed"` (нажато «Тема изучена»); `step_slug` всегда
  строка, у тематических курсов `""`. Это ровно формат `progressFromJson` в `lib/course-progress.ts`.
- Приложение, `app_state`: тот же ключ и та же форма.
- С этапа 2: `courses.position.<slug>` = `{"<lesson>": {"ms": 252000, "updated_at": "<ISO>"}}`.
- «Продолжить» открывает первую непройденную тему последнего открытого курса.
- Тема, исчезнувшая из нового выпуска, просто не показывается; её отметка не мешает.

## Офлайн в приложении

Документ курса кэшируется в `cache_entries` под ключом `courses.document.{slug}.{lang}.{version}`.
При открытии раздела онлайн приложение запрашивает список: новая `version` означает новый документ,
курс, пропавший из списка, скрыт. Без сети показываются сохранённые курсы и баннер.
Видео без интернета не скачивается (решение 6).
