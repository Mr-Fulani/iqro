# Тематические курсы: контракт

Общий контракт для бэкенда, сайта и приложения. Полный план и решения владельца: [plan.md](plan.md).
Здесь только то, о чём три стороны должны договориться заранее: адреса, формат ответов,
разметка конспекта, события обновления кэша, маршруты и ключи хранения.

Этап 1 — курсы с конспектами. Видео (этап 2) и викторина (этап 3) уже описаны в контракте,
чтобы клиенты не пришлось менять потом: на этапе 1 `video` всегда `null`, событий викторины ещё нет.

## Границы

- Новый Django-модуль `quran_backend.modules.courses` («Тематические курсы»). Викторина — отдельный
  модуль `quizzes` (этап 3). Модули `salah` и `tajweed` не меняются.
- «Обучение намазу» и «Таджвид» в API курсов не входят. Клиенты сами ставят их первыми двумя
  карточками каталога и открывают их прежние страницы.
- Зарезервированные slug курса: `salah`, `tajweed`, `quiz`, `courses`, `new`, `preview`, `events`.
- Курс виден на языке, только если у его опубликованного выпуска есть этот язык. Частичных переводов
  нет: курс либо полностью на языке, либо не виден на нём.

## API

Префикс `/api/v1/`, адреса без слеша на конце (как `tajweed/course_urls.py`).
Публичные ответы через `PublicReadOnlyViewMixin`: weak ETag, `304`,
`Cache-Control: public, max-age=300, stale-while-revalidate=86400`.

Параметр `language`: `ru`, `en`, `ar` или `tr`, по умолчанию `ru`. Другое значение даёт `400`
с `{"language": ["Поддерживаются: ar, en, ru, tr."]}`, как в `salah/api.py`.

### `GET /api/v1/courses?language=ru`

Видимые курсы, у которых есть выпуск на этом языке, по `position`, затем по названию.
Пример: [course-list.example.json](course-list.example.json).

| Поле | Тип | Смысл |
|---|---|---|
| `language` | string | Язык ответа |
| `courses[].slug` | string | Адрес курса |
| `courses[].version` | string | Номер опубликованного выпуска, строкой (`"1"`) |
| `courses[].title`, `summary`, `source` | string | Тексты на этом языке; `source` — «Автор и источники», может быть `""` |
| `courses[].cover` | object или `null` | `{url, thumb_url, width, height}`, WebP 16:9 |
| `courses[].lesson_count` | int | Число тем |
| `courses[].minutes` | int | Сумма `minutes` тем |
| `courses[].video_minutes` | int | Сумма длительностей видео, округлённая вверх; на этапе 1 `0` |
| `courses[].published_at` | string | ISO 8601 |

### `GET /api/v1/courses/{slug}?language=ru`

Документ опубликованного выпуска на этом языке. Пример: [course-document.example.json](course-document.example.json).
`404 {"detail": "Такого курса нет."}`, если курса нет, он скрыт или у выпуска нет этого языка.

- `schema_version`: `1`.
- `course`: `slug`, `version`, `language`, `languages` (все языки выпуска), `title`, `summary`, `source`,
  `cover`, `published_at`, `checksum_sha256` (документа на этом языке).
- `lessons[]` по порядку:
  - `slug` — адрес темы внутри курса; `number` — порядковый номер с 1;
  - `title`, `summary`, `minutes` (int);
  - `video` — `null`, если у темы нет видео; иначе `{url, bytes, duration_ms, width, height, spoken_language, poster: {url, small_url, width, height}}`, где `spoken_language` — `""` для видео без речи. Сервер уже выбрал файл для языка документа (озвучка или основное видео, раздел «Видео и озвучки»);
  - `notes` — блоки конспекта (ниже);
  - `sources` — массив строк, по источнику на строку.

Клиенты обязаны игнорировать незнакомые поля. Новое обязательное поле или новый тип блока
поднимает `schema_version`; клиент, получивший больший `schema_version`, показывает «Обновите
приложение» вместо курса.

## Конспект: разметка автора и блоки

Автор пишет конспект простым текстом с пометками. Сервер разбирает его один раз при подготовке
выпуска (`core/editorial/markup.py`) и отдаёт готовые блоки. Сайт и приложение только рисуют блоки,
поэтому показывают одно и то же. HTML и ссылок в разметке нет; всё выводится как текст.

| Пометка автора | Блок |
|---|---|
| пустая строка | граница блоков |
| `## ` в начале строки | `heading` |
| строки `- ` подряд | `list`, `ordered: false` |
| строки `1. `, `2. ` … подряд | `list`, `ordered: true` (номера рисует клиент) |
| строки `> ` подряд | `quote`; последняя строка вида `> — Источник` становится `source` |
| строки `! ` подряд | `note` («Важно») |
| остальное | `paragraph`; одиночный перенос строки — новая строка внутри абзаца |
| `**текст**` | сегмент с `bold: true`; непарные `**` остаются текстом |

Форма блоков:

```text
Segment   = {"text": string, "bold"?: true, "lang"?: "ar"}
heading   = {"type": "heading",   "dir": D, "text": Segment[]}
paragraph = {"type": "paragraph", "dir": D, "lines": Segment[][]}
list      = {"type": "list",      "dir": D, "ordered": bool, "items": Segment[][]}
quote     = {"type": "quote",     "dir": D, "lines": Segment[][], "source": string | null}
note      = {"type": "note",      "dir": D, "lines": Segment[][]}
D         = "ltr" | "rtl"
```

- Заголовок — всегда одна строка. Строка с другой пометкой начинает новый блок и без пустой строки
  перед ней. Источник цитаты отделяется длинным тире и пробелом: `> — Коран, 2:183`.
- `dir` блока определяется по первому «сильному» символу его текста: арабская письменность даёт `rtl`.
- Отрезки арабской письменности (U+0600–U+06FF, U+0750–U+077F, U+08A0–U+08FF, U+FB50–U+FDFF,
  U+FE70–U+FEFF вместе с пробелами и знаками между арабскими словами) становятся отдельными
  сегментами с `lang: "ar"`. Клиент рисует их арабским шрифтом и изолирует направление:
  сайт — `<bdi lang="ar">` со шрифтом `--font-arabic`, приложение — Amiri Quran и U+2068…U+2069.
- Соседние сегменты с одинаковыми признаками склеиваются; пробелы по краям строк обрезаются.
- Разбор никогда не падает: неизвестная пометка остаётся обычным текстом.
- Лимиты на язык: конспект темы до 20 000 символов, источники до 2 000. Документ на язык до 2 МиБ.

Общие примеры «разметка → блоки» для тестов всех трёх сторон: [notes-markup.cases.json](notes-markup.cases.json).
Бэкенд проверяет по ним разбор, клиенты — что рисуют каждый тип блока, `dir` и `lang`.

## Видео и озвучки (этап 2)

Решение владельца 24.10.2026: у темы **одно видео** (картинка и основной звук) и, по желанию,
**отдельные озвучки** для других языков. Сервер склеивает картинку видео с озвучкой языка в отдельный
файл. Картинка при этом копируется, а не пережимается.

**Видео темы** (`CourseVideo`, одно на тему):
- MP4 или MOV, видео H.264 до 1920×1080 и 60 кадров/с, звук AAC или без звука, от 10 секунд до 60 минут,
  до 480 МБ. HEVC, VP9, AV1 и WebM не принимаются, админка объясняет, как пересохранить файл.
- Сервер проверяет файл (`ffprobe`), переупаковывает без пережатия (`-c copy -map_metadata -1
  -movflags +faststart`), делает обложку WebP 1280 и 640 px и кладёт всё в R2:
  `courses/videos/{sha[:20]}.mp4`, `courses/posters/…`.
- `spoken_language` основного звука задаёт автор: `ru`, `en`, `ar`, `tr` или `""` (без речи).

**Озвучка** (`CourseVideoDub`, не больше одной на язык и видео, язык отличен от основного):
- Аудиофайл MP3, M4A/AAC, WAV или FLAC до 200 МБ. Это полный звук языка: голос, музыка и звуки вместе.
- Длительность должна совпадать с видео с точностью ±2 секунды, иначе ошибка с разницей в секундах.
- Сервер кодирует звук в AAC (128 кбит/с) и склеивает с картинкой видео:
  `-map 0:v:0 -map 1:a:0 -c:v copy -shortest -movflags +faststart`. Результат —
  `courses/videos/{video_sha[:20]}-{lang}-{dub_sha[:12]}.mp4`. Файлы в R2 неизменяемые: замена озвучки
  создаёт новый файл.

**Что попадает в документ языка `L`:** файл озвучки `L`, если она есть; иначе основное видео.
`spoken_language` — язык звука этого файла, обложка общая. Новых полей нет, `schema_version` остаётся `1`.
`courses[].video_minutes` в списке — сумма длительностей видео тем, округлённая вверх.

**Проверка рецензентом:** основное видео и каждая озвучка отмечаются «Просмотрено» отдельно, по своему sha.
«Подписать» доступно, когда отмечены все новые и изменённые файлы выпуска.

**Клиенты** (сайт и приложение одинаково):
- До нажатия — только обложка с кнопкой ▶ и подписью «9:48 · 108 МБ»; видео не загружается, пока ученик
  не нажал. Сайт: `<img srcset 640w,1280w>` с `aspect-ratio`, по нажатию `<video controls playsinline
  preload="metadata">`. Приложение: `VideoPlayerController.networkUrl` создаётся по нажатию.
- Если `spoken_language` не пустой и не равен языку документа — пометка «Видео на русском языке»
  (название языка на языке интерфейса).
- Запуск видео ставит на паузу чтение Корана и ду’а: сайт — `lib/audio-focus.ts`, приложение —
  `AudioController`.
- Место остановки сохраняется каждые 5 секунд и при паузе в `courses.position.<slug>`; «Продолжить с 4:12»
  на обложке. Досмотренное до конца видео сбрасывает позицию.
- Приложение: полноэкранный режим отдельным маршрутом (горизонтально), экран не гаснет только пока видео
  играет (`wakelock_plus`), пауза при сворачивании и уходе с экрана, элементы управления в LTR, цели касания
  не меньше 48.
- Адреса видео — только с `media.iqro.forum` (CSP `media-src` на сайте, `isApprovedPublicAssetUri` в приложении).

## Поделиться, оценка, замечания и статистика (этап 4)

Решения владельца 24.10.2026: оценку курса видит **только админ** — ученикам средний балл и звёзды
не показываются; аналитика по курсам — сейчас, по викторинам — на этапе викторины.
Бэкенд — модуль `quran_backend.modules.course_feedback` («Статистика курсов»).

### Поделиться

- Кнопка «Поделиться» на странице курса и на странице темы.
- Ссылка: `https://iqro.forum/{locale}/courses/{course}` или `…/courses/{course}/{lesson}`, где `locale` —
  язык документа курса. Без меток и кодов: `share_referrals` устроен под реферальные ссылки аккаунта
  и награды, курсу он не нужен.
- Телефон: системное меню. Сайт — Web Share API (`navigator.share({title, text, url})`), когда он есть
  и указатель грубый (`(pointer: coarse)`); приложение — `share_plus`, текст `«{название}\n{ссылка}»`.
- Компьютер (и браузер без Web Share): «Скопировать ссылку», после копирования — «Ссылка скопирована».
- Метаданные страниц сайта: `og:title`, `og:description`, `og:image` (обложка курса 1280×720;
  у темы — обложка её видео, если есть, иначе обложка курса), `og:url`, `twitter:card =
  summary_large_image`. Мессенджеры показывают ссылку с картинкой.

### События статистики

`POST /api/v1/courses/events` — без авторизации и cookie (сайт: `fetch(…, {credentials: "omit",
keepalive: true})`), ответ `202 {"accepted": n}`, `Cache-Control: no-store`.

```json
{"platform": "web", "events": [{"course": "ramadan", "lesson": "namerenie", "event": "lesson_opened"}]}
```

- `platform`: `web`, `android`, `ios`. В пачке от 1 до 50 событий, иначе `400`. Лимит
  `QURAN_COURSE_EVENT_RATE` (120 в минуту с адреса; адрес в ключ лимита попадает только как HMAC).
  На `429` и ошибки сети пачка отбрасывается: повторов нет.
- События скрытых и неизвестных курсов и тем вне опубликованного выпуска сервер молча отбрасывает.
- Сервер хранит только суммы за день: `CourseDailyStat(date, course, lesson, platform, event, count)`.
  Человека, устройства, адреса и cookie нет; баннер согласия не нужен, как для объявлений.

| `event` | Когда клиент отправляет |
|---|---|
| `lesson_opened` | Тема открыта (один раз за показ страницы или экрана) |
| `video_started` | Видео темы впервые запущено за показ |
| `video_finished` | Досмотрено до 90 % длительности и дальше, один раз за показ |
| `lesson_completed` | Нажато «Тема изучена», когда тема на устройстве ещё не отмечена (после «Снять отметку» повторная отметка считается снова) |
| `lesson_helpful` | «Полезно» |
| `lesson_not_helpful` | «Не очень» |

Клиенты копят события в очереди и отправляют пачкой **раз в минуту**, а также при уходе со страницы
(сайт: `visibilitychange → hidden` и `pagehide`) или сворачивании приложения (`AppLifecycleState.paused`
или `hidden`) и при закрытии экрана темы. Больше 50 событий — несколькими пачками.

### «Полезно / Не очень»

- В каждой теме под конспектом: «Тема была полезной?» и две кнопки «Полезно» и «Не очень».
- Голос — одно событие статистики. Отдать его можно один раз на тему на устройстве; после этого блок
  показывает «Спасибо за отзыв». Выбор хранится в `courses.vote.<slug>` = `{"<lesson>": "helpful" | "not_helpful"}`
  (сайт — `localStorage`, приложение — `app_state`).

### Оценка курса

`PUT /api/v1/courses/{slug}/rating` — нужен вход, хотя бы гостевой (как избранные дуа: при `401` клиент
создаёт гостевую сессию и повторяет запрос). Ответ `200`, `Cache-Control: private, no-store`.

```json
{"stars": 4, "comment": "Спасибо, всё понятно", "language": "ru", "platform": "android"}
→ {"stars": 4, "comment": "Спасибо, всё понятно", "updated_at": "2027-01-20T10:00:00Z"}
```

- `stars` — от 1 до 5; `comment` — необязательный простой текст до 1000 знаков (HTML и управляющие
  символы — `400`); `language` — язык документа; `platform` — как у событий.
- Одна оценка курса на установку или аккаунт: повторная заменяет прежнюю. Сервер хранит не аккаунт,
  а `voter_digest` = HMAC(секрет, аккаунт + курс) — необратимый и разный для разных курсов. Ещё хранятся
  звёзды, комментарий, язык, платформа и номер выпуска.
- `404 {"detail": "Такого курса нет."}` — курс скрыт или не опубликован. Лимит `QURAN_COURSE_RATING_RATE`
  (20 в час на установку или аккаунт), сверх него `429`.
- Где показывается блок «Насколько курс был полезен?»: на странице курса, если пройдена хотя бы одна тема,
  и на странице последней темы после «Тема изучена». Пять звёзд (группа радиокнопок, у каждой подпись
  «1 из 5»…), поле «Комментарий (необязательно)» со счётчиком до 1000 и «Отправить». После отправки —
  «Спасибо! Ваша оценка: 4 из 5» и «Изменить». Средний балл и чужие оценки ученикам не показываются.
- Своя оценка хранится на устройстве: `courses.rating.<slug>` = `{"stars": 4, "comment": "…", "updated_at": "<ISO>"}`.

### Замечания («Сообщить об ошибке»)

- Кнопка в каждой теме рядом с источниками. Открывает форму: тип замечания, текст (обязательно,
  до 4000), email для ответа (необязательно).
- Типы — существующие категории обращений: `religious_content` «Ошибка в религиозном содержании»,
  `accessibility_localization` «Опечатка или перевод», `technical` «Не работает видео или страница»,
  `other` «Другое».
- Отправка — обычное обращение `POST /api/v1/feedback/tickets` (гостевая сессия при необходимости).
  `subject` — «{курс} · {номер}. {тема}» (до 160 знаков), `locale` — язык документа, `context`:

| Поле `context` | Значение |
|---|---|
| `course_slug`, `lesson_slug` | Курс и тема |
| `content_version` | Номер выпуска (`course.version`) |
| `playback_ms` | Позиция видео, если ученик его запускал |
| `slide_number` | Номер слайда, если у темы есть слайды |
| `route` | `/courses/{course}/{lesson}` |
| `client_platform`, `app_version`, `app_build`, `os_version` | Как в других обращениях |

  `lesson_slug` и `slide_number` требуют `course_slug`, `slide_number` — ещё и `lesson_slug`;
  `playback_ms` разрешён при `lesson_slug`.
- После отправки: «Спасибо! Номер обращения FB-…». Ответ оператора виден в приложении в «Мои обращения»
  (экран обращения открывается только у подтверждённого аккаунта), на сайте — в профиле, раздел «Обратная связь».
- В админке у обращения с курсом сверху блок «Тема курса»: ссылка на тему в админке и на сайте,
  выпуск, секунда видео и слайд. Список обращений фильтруется по курсу (`?course=<slug>`).

### Аналитика в админке

- «Статистика курсов → Курсы: сводка» — все курсы за 7, 30 или 90 дней: открыли и изучили темы,
  начали курс (открыли первую тему), дошли до конца (изучили последнюю), доля «Полезно», средняя оценка,
  число замечаний.
- У курса кнопка «Аналитика» рядом с «Предпросмотр»: воронка по темам (открыли → начали видео →
  досмотрели → изучили), «Где чаще бросают», «Полезно / Не очень» по темам, средняя оценка за период и
  за всё время, распределение звёзд, последние 20 комментариев, число замечаний со ссылкой на них,
  сравнение платформ. Графики — полосы на CSS, без библиотек.
- Права: `course_feedback.view_courseanalytics`; группам «Редактор курсов» и «Публикатор» оно выдано.

## Обновление кэша сайта

Бэкенд после commit отправляет через `enqueue_content_revalidation`:

```json
{"type": "courses.course.changed", "action": "activated", "course": "ramadan", "version": "2"}
{"type": "quizzes.quiz.changed", "action": "withdrawn", "quiz": "ramadan-basics", "version": "1"}
```

`action`: `activated` (публикация, возврат на сайт, откат на прежний выпуск) или `withdrawn` (скрыт).
Сайт принимает оба типа строгим парсером в `lib/content-revalidation.ts` и обновляет:

- курс: теги `courses:catalog`, `courses:course:{slug}`, `quizzes:catalog`; пути `/[locale]/courses`,
  `/[locale]/courses/[course]`, `/[locale]/courses/[course]/[lesson]`;
- викторину: теги `quizzes:catalog`, `quizzes:quiz:{slug}`; пути `/[locale]/quiz`, `/[locale]/quiz/[quiz]`.

PR сайта с этими типами выкатывается **раньше** бэкенда: неизвестный тип получает `422`, а бэкенд
не повторяет ответы 4xx (`app/api/internal/content-revalidation/route.ts`, `core/tasks.py`).

## Маршруты и вход

| | Сайт | Приложение |
|---|---|---|
| Каталог | `/{locale}/courses` | `/courses` |
| Курс | `/{locale}/courses/{course}` | `/courses/:course` |
| Тема | `/{locale}/courses/{course}/{lesson}` | `/courses/:course/:lesson` |
| Вход | шапка: «Курсы» вместо «Обучение намазу» и «Таджвид»; подвал; «Ещё» на телефоне | плитка «Курсы» в «Ещё» |

Прямые входы в «Обучение намазу» и «Таджвид» остаются в подвале сайта и на экране «Намаз», а в «Ещё»
на телефоне и в приложении их заменяет «Курсы».
Пункт «Викторина» появляется в навигации только на этапе 3, вместе с самим разделом.
Пять нижних вкладок приложения не меняются.

## Прогресс на устройстве

Решение 5: на старте прогресс хранится только на устройстве. Формат совпадает с
`lib/course-progress.ts`, чтобы синхронизация с аккаунтом потом включилась без переделки.

- Сайт, `localStorage`: `courses.progress.<slug>` = `{"lessons": {"<lesson>": {"status": "completed", "step_slug": "", "content_version": "<version>", "updated_at": "<ISO>"}}}`.
  `status` — `"in_progress"` (тема открыта) или `"completed"` (нажато «Тема изучена»); `step_slug` всегда
  строка, у тематических курсов `""`. Это ровно формат `progressFromJson` в `lib/course-progress.ts`.
- Приложение, `app_state`: тот же ключ и та же форма.
- С этапа 2: `courses.position.<slug>` = `{"<lesson>": {"ms": 252000, "updated_at": "<ISO>"}}`.
- «Продолжить» открывает первую непройденную тему последнего открытого курса.
- Тема, исчезнувшая из нового выпуска, просто не показывается; её отметка не мешает.

## Офлайн в приложении

Документ курса кэшируется в `cache_entries` под ключом `courses.document.{slug}.{lang}.{version}`.
При открытии раздела онлайн приложение запрашивает список: новая `version` означает новый документ,
курс, пропавший из списка, скрыт. Без сети показываются сохранённые курсы и баннер.
Видео без интернета не скачивается (решение 6).
