# Переход к самостоятельной локальной разработке

## Поведение

PDF-страница больше не предлагается в web/mobile. Web выбирает доступный макет
Quran.Foundation и показывает его официальным шрифтом. Mobile выбирает опубликованный
набор изображений с областями аятов; локальная команда готовит все 604 страницы KFGQPC.
При пустом каталоге клиент сообщает, что содержимое ещё не подготовлено.

Переходы по аятам, жесты, аудио, сохранение позиции, закладки и offline-хранение
используют общие механизмы. Изображение страницы больше не является условием существования
канонического текста и навигации.

## Существующая БД

Миграция `quran.0007_canonical_page_mapping` создаёт `AyahPageMapping` и переносит
уникальные связи из старых областей аятов. UUID сур, аятов и страниц сохраняются.
Исторические таблицы и поля остаются для совместимости данных; активная навигация
от них не зависит. Применённые миграции не переписываются.

Импорт канонического корпуса проверяет SHA-256, 114 сур, 6236 аятов, 604 страницы
и границы разделов. При уже опубликованной версии он сверяет текст и связи, сохраняя UUID.
Если существующие данные отличаются, импорт останавливается до отдельной миграции
соответствия. Старый API изображений отвечает 410 с кодом `mushaf_endpoint_retired`.
Команды подготовки и публикации PDF удалены; импорт проверенных исторических dataset
пакетов сохранён для совместимости.

## Новое окружение

Основной путь описан в [локальной разработке](local-development.md) и главном README:
`dev-init` → заполнение ключей → `make up` (либо `make mobile-run`).
Команда запуска сама применяет миграции и подготавливает недостающее содержимое.
Готовый опубликованный корпус старой БД не импортируется заново; отдельный ручной
`import_quran_corpus` по-прежнему отклоняет несовместимую замену.
Содержимое берётся из закреплённых публичных источников, QF API и встроенных каталогов
ду’а. Дамп коллеги, частные медиа и общий тестовый сервер не требуются.

Исходники, шрифт, каждый WebP и итоговый manifest проверяются контрольными суммами.
Повторный рендер проверяет существующие файлы; частичный набор не публикуется.
Локальные HTTP/медиа разрешены только в debug/local. Ограничения profile/release
и публикации в production сохранены.

## Проверки

В автоматических тестах проверяются перенос старых связей, неизменность UUID,
повторные импорты, неполные источники, повреждённые файлы, запрет частичной публикации,
отдельные checkpoints QF, выбор доступного Мусхафа, локальные URL и offline-проверки.
Проверки рендера также сравнивают последовательный и параллельный результат.

Проверка запуска выполнена в отдельной копии исходников с новой PostgreSQL и пустыми
медиа: миграции, загрузка настоящего QF source 5, канонического корпуса и обоих полных
каталогов ду’а. Повторный `dev-up` сохраняет рабочее окружение.

### Результаты проверки 2026-09-13

- Backend: 778 тестов в полном прогоне; дополнительно прошли тест local-расписания
  и тест публикации настоящего полного пакета. Покрытие полного прогона — 83,49%;
  у импорта канонического корпуса и локального хранилища — 100% строк и ветвей.
- Flutter: 388 обычных тестов, анализатор без ошибок, Android debug APK собран.
  Отдельно декодированы все 1812 WebP и проверены области 6236 аятов в двух размерах
  экрана. Интеграционный тест получил полный manifest и изображения через настоящий
  HTTP API отдельной локальной копии.
- Web: 53 браузерных сценария читалки и сохранения позиции; lint и TypeScript прошли.
  На реальном API отдельно открыты страницы 1 и 604 с официальным шрифтом и выделением аятов.
  Production-сборка и проверка её целостности прошли в закреплённом Docker-окружении Node.js 22.
- Генератор: проверки источника, типографики, одинаковых результатов последовательного
  и параллельного запуска, повреждения кеша и lossless-кодирования.
- Запуск окружения: 11 тестов. Реальный PostgreSQL-дамп восстановлен в новую тестовую БД;
  подтверждены 6236 аятов и 604 страницы. Дамп создаётся с правами `0600`.

Вторая копия самостоятельно загрузила корпус, QF snapshot, шрифт и ду’а. Для проверки
возобновления ей передан проверенный кеш уже сформированных страниц; её собственные
`dev-data` и `dev-doctor` полностью прошли, включая проверку всех файлов и публикацию
в отдельные БД/media. База другой рабочей копии не использовалась как dev-дамп.

Обычные тесты пропускают проверки, требующие внешних полных пакетов. Полный KFGQPC
и локальный API проверены отдельными запусками с переменными окружения; дополнительные
полные QCF/Tajweed-пакеты в этот прогон не входили.

### Проверка автоматической подготовки при запуске, 2026-09-13

- `make up` теперь сам подготавливает содержимое; `make mobile-run` сначала выполняет
  тот же запуск. Web и фоновые задачи запускаются после успешной подготовки данных.
- Прошли 19 тестов управляющего скрипта и 12 тестов готовности данных/канонического
  корпуса. Проверены отсутствие ключей, сбой источника, продолжение с недостающего
  ресурса, блокировка параллельного запуска и повреждение мобильного файла того же размера.
  Ruff, форматирование и проверка типов изменённой backend-команды прошли.
- В существующей локальной БД автоматически загружены все 15 переводов и 13 тафсиров
  из стандартной конфигурации. Опубликованный канонический корпус сохранён.
  Повторный запуск не импортировал данные и не запускал рендер.
- На настоящем localhost в браузере проверены включение/выключение перевода и тафсира
  в текстовой читалке и Мусхафе; содержимое приходит из локального API.
- Отдельная копия исходников с новой PostgreSQL самостоятельно загрузила QF source 5,
  корпус, ду’а, все настроенные переводы/тафсиры и аудио: 114 сур, 6236 таймкодов аятов.
  Дамп исходной БД не использовался. Проверка выполнялась с готовыми Docker-образами
  (`--no-build`) и кешем зависимостей: повторная сборка образов упёрлась в нехватку места.
- Для мобильных страниц повторно использованы проверенные изображения после сверки
  всех слов, SVG и областей аятов с новым снимком QF. Генератор проверил все 604 страницы,
  затем обычный запуск опубликовал их в отдельные БД/media. После прерывания рендера
  повторный `make up` выполнил только мобильный шаг; все каталоги сохранились.
  Flutter через настоящий API проверил manifest 604 страниц, 6236 UUID аятов,
  контрольные суммы и декодирование изображений первой и последней страниц.
- Повторный запуск готовой новой БД завершился без импорта и рендера. Сравнение
  контрольной суммы UUID/текстов всех 6236 аятов подтвердило их неизменность;
  каноническая версия также сохранилась.
