# Выпуск Android-приложения в Google Play

Пошаговая инструкция для владельца: что сделать один раз, как собрать и загрузить выпуск
и что отвечать в анкетах Play Console. Тексты страницы приложения —
в [google-play-listing.md](google-play-listing.md).

Состояние на 26.10.2026:

- приложение `forum.iqro.app`, версия `1.0.0` (код сборки `1`), `targetSdk 36`, `minSdk 24`;
- релизный пакет AAB из `main` собирается (`flutter build appbundle --release`, около 61 МБ,
  R8 и сжатие ресурсов включены), но без подписи: ключа загрузки ещё нет;
- релизная сборка на телефоне не проверялась, только отладочная.

## 1. Аккаунт разработчика

1. https://play.google.com/console → создать аккаунт разработчика, разовый взнос 25 $.
2. Тип аккаунта:
   - **Личный** — быстрее, но перед выходом в общий доступ нужно закрытое тестирование:
     не меньше 12 человек, подписанных на тест 14 дней подряд;
   - **Организация** — без этого требования, но нужен номер D-U-N-S организации.
3. Подтвердить личность и телефон, как попросит Play Console.
4. Почту разработчика для страницы приложения указать ту же, что в политике: `fulani.dev@gmail.com`.

## 2. Ключ загрузки

Google хранит итоговый ключ подписи сам (Play App Signing). Нам нужен только **ключ загрузки**:
им подписывается каждый AAB перед отправкой. Если ключ загрузки потерять, его можно заменить через
поддержку Play, но это долго — поэтому сразу две копии.

1. В Терминале на Mac (пароли придумываете и вводите сами, в чат их не пишите):

   ```bash
   mkdir -p ~/Documents/IQRO-play-key
   /Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home/bin/keytool -genkeypair -v -keystore ~/Documents/IQRO-play-key/iqro-upload.jks -alias iqro-upload -keyalg RSA -keysize 4096 -validity 10000
   ```

2. Создать файл `clients/iqro_mobile/android/key.properties` (он в `.gitignore`, в git не попадёт):

   ```properties
   storeFile=/Users/user/Documents/IQRO-play-key/iqro-upload.jks
   storePassword=<пароль хранилища>
   keyAlias=iqro-upload
   keyPassword=<пароль ключа>
   ```

3. Копия ключа и паролей — в заблокированную заметку, как ключ бэкапов («IQRO ключ загрузки Play»),
   плюс файл `iqro-upload.jks` во второе надёжное место. Ключ не кладётся ни в git, ни на сервер.

## 3. Сборка выпуска

Из чистой копии `main`:

```bash
cd clients/iqro_mobile
flutter build appbundle --release --dart-define=APP_ENV=production --dart-define=API_BASE_URL=https://iqro.forum --dart-define-from-file=config/firebase.json
```

- Отчёты о падениях: добавить `--dart-define=SENTRY_DSN=<DSN проекта мобильного приложения>`.
  Без него Sentry в приложении выключен (так было во всех сборках до сих пор).
- Номер сборки растёт с каждой загрузкой: `version: 1.0.0+1` в `pubspec.yaml`, следующая — `1.0.0+2`
  или `1.0.1+2`. Play не примет сборку с уже использованным кодом.
- Готовый файл: `build/app/outputs/bundle/release/app-release.aab`. Проверить подпись:
  `jarsigner -verify app-release.aab` должен ответить `jar verified`.

Проверка релизной версии на телефоне: Redmi сейчас с отладочной сборкой, подписанной другим ключом,
поэтому релизную поверх не поставить без удаления приложения (это стёрло бы данные). Релиз проверяется
через **внутреннее тестирование** Play: телефон ставит его из Play как отдельную установку после
удаления отладочной сборки — данные заранее синхронизировать через аккаунт.

## 4. Тестирование и выпуск

1. **Внутреннее тестирование** (до 100 человек, без проверки Google): загрузить AAB, добавить свой
   Google-аккаунт, поставить из Play на телефон, пройти основные сценарии.
2. **Закрытое тестирование** (для личного аккаунта обязательно): 12+ тестировщиков, 14 дней подряд.
   Список почт или Google-группа; ссылку на тест разослать им.
3. **Рабочая версия**: после закрытого теста Play Console откроет «Подать заявку на доступ
   к рабочей версии». Выпуск сначала на 10–20 % пользователей, через пару дней без падений — на всех.

## 5. Ответы в Play Console

### Политика конфиденциальности

`https://iqro.forum/ru/privacy` (есть на ru, en, ar, tr).

### Удаление аккаунта

- В приложении: «Профиль» → удаление аккаунта (подтверждение по почте, 7 дней на отмену).
- Ссылка без приложения: `https://iqro.forum/ru/data-rights` — там описано удаление аккаунта
  через сайт или по письму.
- Удаляются: аккаунт, почта, синхронизированные данные; рабочая копия — за 30 дней,
  копии в резервных архивах — за 90 дней.

### Доступ к приложению

Всё работает без входа (гостевой режим). Вход по коду из письма нужен только для синхронизации.
Отметить: «Все функции доступны без особого доступа».

### Реклама

Рекламы нет. Рекламный идентификатор не собирается: разрешение `AD_ID` удалено из манифеста.
Ответ: «Нет, приложение не использует рекламный идентификатор».

### Безопасность данных

Общие ответы:

- Собирает или передаёт данные пользователей: **Да**.
- Все данные шифруются при передаче: **Да** (только HTTPS, `usesCleartextTraffic=false`).
- Пользователь может запросить удаление данных: **Да**.
- Передача третьим лицам: **Нет**. Firebase (Google) и Sentry работают как обработчики от нашего
  имени — по правилам Play это не «передача».

Собираемые данные:

| Категория Play | Тип | Обязательно? | Зачем | Когда |
|---|---|---|---|---|
| Личная информация | Адрес электронной почты | Необязательно | Управление аккаунтом, функции приложения | только при входе |
| Местоположение | Приблизительное местоположение | Необязательно | Функции приложения (время намаза и напоминания); аналитика — город по IP, только с согласия | по разрешению или с согласия на статистику |
| Действия в приложении | Взаимодействие с приложением | Необязательно | Аналитика (события: открыта сура, включено аудио, тема изучена, «Поделиться», вход) | только с согласия на статистику |
| Действия в приложении | Другой пользовательский контент | Необязательно | Функции приложения (закладки, заметки, план чтения, прогресс — синхронизация) | при входе |
| Сообщения | Другие сообщения в приложении | Необязательно | Поддержка (обращения и ответы) | при обращении |
| Информация и производительность приложения | Журналы сбоев, Диагностика | Необязательно | Аналитика, исправление ошибок | только если сборка с `SENTRY_DSN`; иначе не отмечать |
| Идентификаторы устройства или другие | Идентификаторы устройства | Обязательно | Функции приложения (ключ установки для синхронизации и защиты), безопасность; аналитика — идентификатор экземпляра Firebase, с согласия | всегда / с согласия |

Не собираются: финансовые данные, здоровье, контакты, фото и видео, аудиозаписи с микрофона,
файлы, календарь, веб-история, точное местоположение (разрешение только `ACCESS_COARSE_LOCATION`).

Отметка «данные обрабатываются эфемерно» — нет; «сбор можно отключить» — да для статистики
(«Настройки» → статистика), местоположения и почты.

### Разрешения, требующие объяснения

| Разрешение | Ответ |
|---|---|
| `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | Декларация служб переднего плана: тип «Воспроизведение мультимедиа». Пользователь запускает чтение Корана и слушает его со свёрнутым приложением или выключенным экраном; уведомление с кнопками плеера видно всё время. Нужно видео 30–60 с: включить суру → свернуть → управлять из шторки и с экрана блокировки. |
| `SCHEDULE_EXACT_ALARM` | Отдельной декларации не требует (ограничено только `USE_EXACT_ALARM`). На Android 14+ выключено по умолчанию: онбординг объясняет и ведёт в настройки, без него напоминания о намазе приходят неточно. |
| `ACCESS_COARSE_LOCATION` | Только время намаза для города пользователя; можно выбрать город вручную. |
| `RECEIVE_BOOT_COMPLETED` | Восстановить напоминания о намазе после перезагрузки. |

и так не рассчитана на самостоятельное использование детьми.

## 7. Перед каждым следующим выпуском

1. Поднять номер сборки в `pubspec.yaml`.
2. Собрать AAB из чистой копии `main` (раздел 3), проверить подпись.
3. Загрузить во внутреннее тестирование, поставить на телефон, проверить.
4. Перевести тот же выпуск в рабочую версию с поэтапным выпуском.
5. В «Что нового» — коротко на 4 языках.
