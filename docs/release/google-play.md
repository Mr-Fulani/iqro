## 1. Аккаунт разработчика

1. https://play.google.com/console → создать аккаунт разработчика, разовый взнос 25 $.
2. Тип аккаунта:
   - **Личный** — быстрее, но перед выходом в общий доступ нужно закрытое тестирование:
     не меньше 12 человек, подписанных на тест 14 дней подряд;
   - **Организация** — без этого требования, но нужен номер D-U-N-S организации.
3. Подтвердить личность и телефон, как попросит Play Console.
4. Почту разработчика для страницы приложения указать ту же, что в политике: `fulani.dev@gmail.com`.

## 2. Ключ загрузки

Google хранит итоговый ключ подписи сам (Play App Signing). Нам нужен только **ключ загрузки**:
им подписывается каждый AAB перед отправкой. Если ключ загрузки потерять, его можно заменить через
поддержку Play, но это долго — поэтому сразу две копии.

1. В Терминале на Mac (пароли придумываете и вводите сами, в чат их не пишите):

   ```bash
   mkdir -p ~/Documents/IQRO-play-key
   /Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home/bin/keytool -genkeypair -v -keystore ~/Documents/IQRO-play-key/iqro-upload.jks -alias iqro-upload -keyalg RSA -keysize 4096 -validity 10000
   ```

2. Создать файл `clients/iqro_mobile/android/key.properties` (он в `.gitignore`, в git не попадёт):

   ```properties
   storeFile=/Users/user/Documents/IQRO-play-key/iqro-upload.jks
   storePassword=<пароль хранилища>
   keyAlias=iqro-upload
   keyPassword=<пароль ключа>
   ```

3. Копия ключа и паролей — в заблокированную заметку, как ключ бэкапов («IQRO ключ загрузки Play»),
   плюс файл `iqro-upload.jks` во второе надёжное место. Ключ не кладётся ни в git, ни на сервер.

## 3. Сборка выпуска

Из чистой копии `main`:

```bash
cd clients/iqro_mobile
flutter build appbundle --release --dart-define=APP_ENV=production --dart-define=API_BASE_URL=https://iqro.forum --dart-define-from-file=config/firebase.json
```

- Отчёты о падениях: добавить `--dart-define=SENTRY_DSN=<DSN проекта мобильного приложения>`.
  Без него Sentry в приложении выключен (так было во всех сборках до сих пор).
- Номер сборки растёт с каждой загрузкой: сейчас `version: 1.0.8+9` в `pubspec.yaml`, следующая —
  `1.0.9+10`. Play не примет сборку с уже использованным кодом.
- Готовый файл: `build/app/outputs/bundle/release/app-release.aab`. Проверить подпись:
  `jarsigner -verify app-release.aab` должен ответить `jar verified`.

Проверка релизной версии на телефоне: на Redmi `forum.iqro.app` 1.0.4 стоит из Play (установщик
`com.android.vending`, проверено 06.11.2026). Тестовая сборка «IQRO тест» (`forum.iqro.app.test`)
собирается локально с временным `applicationIdSuffix = ".test"`, в git его нет. Это два разных
приложения, они стоят рядом, поэтому выпуск из Play ставится без удаления тестовой сборки.

## 4. Тестирование и выпуск

1. **Внутреннее тестирование** (до 100 человек, без проверки Google): загрузить AAB, добавить свой
   Google-аккаунт, поставить из Play на телефон, пройти основные сценарии.
2. **Закрытое тестирование** (для личного аккаунта обязательно): 12+ тестировщиков, 14 дней подряд.
   Список почт или Google-группа; ссылку на тест разослать им.
3. **Рабочая версия**: после закрытого теста Play Console откроет «Подать заявку на доступ
   к рабочей версии». Выпуск сначала на 10–20 % пользователей, через пару дней без падений — на всех.

## 8. Обновления внутри приложения

Начиная с 1.0.2 Android-приложение само узнаёт о новой версии в Google Play
(Play In-App Updates, только гибкое обновление FLEXIBLE). Код:
`lib/features/app_update/`, `lib/core/platform/play_app_update.dart`,
`android/.../AppUpdateHandler.kt`.

Как это выглядит для тестировщика:

1. При запуске и при возврате в приложение, **не чаще раза в 30 минут**, приложение спрашивает Play,
   есть ли новая версия. Найденное обновление запоминается (`AppUpdateRecord.offerVersion`): если
   приложение запустили заново раньше, чем через 30 минут (MIUI часто выгружает его из памяти),
   Play не спрашивается, а плашка и строка в «Ещё» показываются по памяти, пока на телефоне
   версия старее. До 1.0.7 обновление в этом случае пропадало до следующей проверки.
2. Если есть — над нижней панелью карточка «Доступна новая версия IQRO»: сверху зелёно-золотая
   полоса, слева значок, под текстом номер установленной сборки «У вас 1.0.5 (6)», внизу две
   равные кнопки «Позже» и «Обновить».
3. «Обновить» → окно Play → обновление скачивается в фоне, приложением можно пользоваться.
   Пока оно качается, на карточке «Обновление загружается» и полоса загрузки вместо кнопок.
4. Когда скачалось — «Обновление загружено» и кнопки «Позже» и «Перезапустить»: Play ставит новую
   версию и открывает приложение заново. «Позже» здесь скрывает плашку до следующего запуска.
5. «Позже» на первой плашке (или «Нет» в окне Play) скрывает эту версию на 3 дня; более новая
   версия предлагается сразу.
6. **С 1.0.7** обновление, пока оно не установлено, всегда есть первой строкой в «Ещё → Аккаунт»
   (`AppUpdateTile`), в том числе после «Позже»: «Доступна новая версия IQRO», «У вас 1.0.6 (7)»,
   золотая точка и кнопка «Обновить» (или «Открыть Google Play»); пока качается — полоса
   загрузки; когда скачалось — «Перезапустить». «Позже» скрывает только плашку
   (`AppUpdateState.hidden`), обновление из «Ещё» не пропадает.

Установки не из Play (отладочные сборки, APK через adb) ничего не показывают: Play отвечает, что
приложение установлено не им, и проверка молча завершается. На iOS проверки нет.

**Запасная проверка через сервер (с 1.0.6).** Play сообщает приложению о новой версии только
после того, как Play Маркет обновит у себя сведения, а это бывает через сутки: при выходе 1.0.4
и 1.0.5 тестировщики плашку не увидели. Поэтому, если Play молчит, приложение спрашивает
`GET /api/v1/app/release` (`android_version_code`, ответ кэшируется на 5 минут). Номер задаётся
в админке «Объявления → Последняя версия приложения»; 0 — не проверять. Если он больше кода
установленной сборки, появляется та же плашка с текстом «Откроется страница IQRO в Google Play,
там нажмите «Обновить»» и кнопкой «Открыть Google Play»: она открывает страницу IQRO в Play
Маркете, «Позже» скрывает
эту версию на 3 дня. Когда Play сам знает об обновлении, работает обычное гибкое обновление,
а сервер не спрашивается. Установки не из Play сервер тоже не спрашивают.

Код сборки видно в приложении: внизу экрана «Ещё» строка «IQRO · Версия 1.0.6 (7)». Его же
показывает Play Console у выпуска, так тестировщик может сам сравнить версии.

**Плашка обновления.** При выходе 1.0.4 владелец увидел обновление только на странице
приложения в Play Маркете, при выходе 1.0.5 плашку не увидели и тестировщики. Play отвечает по
сохранённым у себя сведениям, поэтому плашка от Play может появиться позже; с 1.0.6 это
закрывает запасная проверка через сервер (выше). Версии до 1.0.6 её не знают: их владельцам
можно сообщить об обновлении объявлением только для Android с «Максимальной версией приложения»
и кнопкой на `https://play.google.com/store/apps/details?id=forum.iqro.app`. Телефон на дорожке
Alpha не видит выпуск внутреннего тестирования.

### Проверка через Internal App Sharing (быстро, без выпуска в трек)

Нужен **отдельный тестовый телефон** или телефон без IQRO: приложение из Internal App Sharing
подписано другим ключом, поэтому встаёт только после удаления прежней установки. На Redmi
с отладочной сборкой владельца так не делать — удаление сотрёт данные.

1. Play Console → «Внутренний доступ к приложениям» (Internal app sharing): включить, добавить
   свой Google-аккаунт в загрузчики и тестировщики.
2. На телефоне: Play Маркет → Настройки → «О приложении» → 7 раз нажать «Версия Play Маркета»,
   затем в настройках включить «Внутренний доступ к приложениям».
3. **Выпуск N**: собрать AAB (раздел 3) с текущим номером, например `1.0.2+3`, загрузить на
   https://play.google.com/console/internal-app-sharing, открыть ссылку на телефоне, установить.
   **Пока не запускать приложение** (иначе первая проверка пройдёт сейчас, а следующая — только
   через 30 минут).
4. **Выпуск N+1**: поднять номер (`1.0.3+4`), собрать, загрузить, открыть новую ссылку на телефоне,
   но **не нажимать «Обновить»** в Play — достаточно, чтобы Play увидел версию.
5. Запустить IQRO (выпуск N) → появляется плашка «Доступна новая версия IQRO».
6. «Обновить» → окно Play → дождаться «Обновление загружено» → «Перезапустить». Приложение
   открывается заново; в сведениях о приложении Android (долгое нажатие на значок → «О приложении»)
   видна версия N+1, плашки больше нет.

Если плашки нет: закрыть приложение, открыть ссылку N+1 ещё раз, подождать минуту, запустить снова.
Если приложение уже запускалось после установки N, проверка повторится через 30 минут.

### Проверка через внутреннее тестирование (как увидят тестировщики)

1. В треке «Внутреннее тестирование» опубликован выпуск N, телефон тестировщика поставил его из Play.
2. Загрузить выпуск N+1 с большим кодом сборки в тот же трек и дождаться статуса «Опубликовано»
   (обычно минуты, иногда до нескольких часов).
3. На телефоне открыть страницу IQRO в Play Маркете, чтобы он обновил сведения о версиях.
   Кнопку «Обновить» в Play не нажимать.
4. Запустить IQRO или вернуться в него. Если проверка уже была меньше 30 минут назад, плашка
   появится при первом запуске или возврате после этого срока.
5. Дальше — как в шагах 6 выше.

То же увидят тестировщики закрытого теста Alpha: им достаточно открывать приложение — письмо
в группу `iqro-testers` остаётся для тех, кто давно не заходил.

### Обязательное обновление (по умолчанию выключено)

Режим «без кнопки „Позже“» включается при сборке:
`--dart-define=APP_UPDATE_MANDATORY_PRIORITY=4`. Тогда версия с приоритетом 4 или 5 предлагается
без «Позже» (всё равно гибким обновлением, IMMEDIATE не используется). Приоритет выпуску задаётся
только через Google Play Developer API (`inAppUpdatePriority` в `edits.tracks`), в Play Console
его поставить нельзя; без него приоритет 0. Флаг действует в уже установленной версии, то есть
должен быть в сборках *до* той, которую нужно сделать обязательной.

## 9. Ссылки iqro.forum в приложении (Android App Links)

Приложение объявляет ссылки `https://iqro.forum/...` (дуа, намаз, курсы) с `android:autoVerify="true"`
(`clients/iqro_mobile/android/app/src/main/AndroidManifest.xml`). Android открывает их в приложении,
только если сайт подтверждает подпись в `https://iqro.forum/.well-known/assetlinks.json`. Иначе
ссылка открывается в браузере.

Файл собирает сайт (`services/web/lib/mobile-association.ts`) из переменной
`ANDROID_APP_LINK_SHA256_CERT_FINGERPRINTS` в `services/backend/.env.production`. Пустая переменная
даёт `[]`.

Отпечатки SHA-256 (не секрет, сайт отдаёт их всем):

| Ключ | Откуда | SHA-256 |
|---|---|---|
| Ключ подписи Google Play: им подписаны все установки из Play | Play Console → «Подписи приложений», готовый блок Digital Asset Links | `B8:F9:2A:C3:38:6D:40:24:E6:12:15:00:A6:FB:7C:01:BF:4B:1A:62:E8:76:80:37:8C:ED:49:96:11:BE:B8:A2` |
| Ключ загрузки: им подписаны AAB до Play и сборки, поставленные мимо Play | `keytool -printcert -jarfile iqro-<версия>.aab`, пароль не нужен | `79:D8:9D:D8:18:0E:61:28:26:5E:3F:FD:35:31:C6:2A:9F:25:FF:F7:04:FE:FA:1B:1C:32:4A:2F:C5:2F:4C:5A` |

Строка для `.env.production`:

```
ANDROID_APP_LINK_SHA256_CERT_FINGERPRINTS=B8:F9:2A:C3:38:6D:40:24:E6:12:15:00:A6:FB:7C:01:BF:4B:1A:62:E8:76:80:37:8C:ED:49:96:11:BE:B8:A2,79:D8:9D:D8:18:0E:61:28:26:5E:3F:FD:35:31:C6:2A:9F:25:FF:F7:04:FE:FA:1B:1C:32:4A:2F:C5:2F:4C:5A
```

На проде задано 06.11.2026 (копия прежнего файла: `.env.production.bak-20261106-applinks`). Порядок при смене ключа (только с «да» владельца на выкладку): резервная копия, строка в `.env.production`,
перезапуск web обычной выкладкой, затем проверка:

```
curl -s https://iqro.forum/.well-known/assetlinks.json
```

Проверено 09.11.2026: сервис Google Digital Asset Links видит оба отпечатка, а на Redmi у
`forum.iqro.app` из Play домен `iqro.forum` подтверждён (`dumpsys package d`: `always`), то есть
ссылки открываются в приложении. Если Play Console пишет «13 ссылок… домены не связаны», сначала
проверить эти два признака: до 06.11.2026 файл был пустым, и Play мог запомнить ту проверку.

В ответе должен быть `forum.iqro.app` с обоими отпечатками. Android проверяет ссылки при установке
или обновлении приложения. Уже установленное приложение подхватит подтверждение после следующего
обновления из Play. Посмотреть результат на телефоне:
`adb shell pm get-app-links forum.iqro.app` (у `iqro.forum` должно быть `verified`).

Тестовое приложение `forum.iqro.app.test` в файл не входит: его ссылки открываются в браузере, так задумано.
