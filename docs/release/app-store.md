# IQRO на iPhone: инструкция владельцу

Что сделать, чтобы IQRO вышло в App Store: вступить в программу Apple, подготовить подпись,
получить первую сборку на свой iPhone через TestFlight и заполнить анкеты. Xcode на Mac не
нужен: сборка идёт в GitHub.

- Что проверить на iPhone — [ios-testflight-checklist.md](ios-testflight-checklist.md).
- Тексты страницы App Store — [app-store-listing.md](app-store-listing.md).
- Android — [google-play.md](google-play.md).

Сверено 27.11.2026: сайты Apple (developer.apple.com, справка App Store Connect, App Review
Guidelines в редакции 16.10.2026) и код `main` `a1c7b7ce`.

Как читать:

- **жирным** — кнопки и поля. На сайтах Apple и в приложении Apple Developer — по-английски
  (если сайт у вас по-русски, названия другие, порядок тот же); на iPhone, в TestFlight и
  на Mac — по-русски;
- 🔶 — нужно ваше решение;
- «сессии» — сессии Claude, которые сейчас правят код для iPhone.

## 1. Вступить в Apple Developer Program

Если ещё не вступили. Проще всего — с iPhone, в приложении Apple Developer. Ему нужна
iOS 26 или новее; если на iPhone iOS старше, вступайте на сайте
https://developer.apple.com/programs/enroll/ — там платят своей картой.

Заранее, в «Настройках» iPhone → ваше имя:

- включена двухфакторная защита;
- имя и фамилия — настоящие, как в паспорте. Псевдоним нельзя: это имя будет видно
  в App Store как продавец;
- в «Оплата и доставка» есть карта на ваше имя.

Шаги. Русского языка в приложении нет, кнопки по-английски.

1. App Store → поставьте и откройте приложение **Apple Developer**.
2. Вкладка **Account** → войдите своим Apple Account. Если попросит — **Agree**.
3. **Enroll Now** → **Continue**.
4. Имя, фамилия и телефон, если спросит. Сфотографируйте паспорт: Apple считает с него
   имя и адрес и сверит их. Адрес — настоящий, без абонентского ящика.
5. **Continue** → тип **Individual** (физлицо) → соглашение программы → **Agree**.
6. **Subscribe** — **99 $ в год**, в местной валюте, где можно, иногда с налогом. Подписка
   продлевается сама. Баланс Apple Account и подарочные карты не принимаются.
7. Ждите письма о вступлении. Если через 24 часа после оплаты его нет — не платите второй
   раз, напишите в поддержку https://developer.apple.com/contact/ и укажите номер заявки
   (Enrollment ID).

Если подписку не продлить, IQRO нельзя будет скачать и обновить. У тех, кто уже поставил,
приложение продолжит работать. После продления бесплатное приложение вернётся в течение
суток.

Когда Apple обновляет соглашение, его принимаете вы — там, куда ведёт баннер: на
https://developer.apple.com/account или в App Store Connect → **Business** → **Agreements**.
Иначе пропадёт доступ к App Store Connect и не создать приложение. Налоги, банк и Paid Apps
для бесплатного приложения не нужны: они только для продаж. Статус трейдера ЕС — в том же
разделе **Business**, см. раздел 10.

## 2. Team ID — прислать в чат

1. https://developer.apple.com/account → **Membership details**.
2. **Team ID** — 10 знаков, латиница и цифры.
3. Пришлите его в чат. Он не секретный.

По нему Claude по вашему «да» задаст в GitHub переменную `APPLE_TEAM_ID` и подготовит файл
связи сайта с приложением: тогда ссылки iqro.forum будут открывать IQRO. Выкладка на
сервер — по вашему слову.

Сразу же попросите доступ к ключам API (раздел 5, шаг 2): Apple одобряет его не мгновенно.

## 3. Группа и два App ID

https://developer.apple.com/account/resources/identifiers

1. **+** → **App Groups** → **Continue**.
   - Description: `IQRO widgets`
   - Identifier: `group.forum.iqro.app`

   **Continue** → **Register**.
2. **+** → **App IDs** → **Continue** → **App** → **Continue**.
   - Description: `IQRO`
   - Bundle ID: **Explicit**, `forum.iqro.app`
   - В **Capabilities** отметьте три:
     - **App Groups** — виджеты берут данные у приложения;
     - **Associated Domains** — ссылки iqro.forum открывают приложение;
     - **Time Sensitive Notifications** — азан ко времени намаза проходит сквозь «Не
       беспокоить», «Сон» и другие режимы фокусирования (но не сквозь беззвучный режим).
       Решено 27.11.2026 (Р3).

   **Continue** → **Register**.
3. **+** → **App IDs** → **Continue** → **App** → **Continue**.
   - Description: `IQRO widgets`
   - Bundle ID: **Explicit**, `forum.iqro.app.PrayerTimesHomeWidget`
   - В **Capabilities** — только **App Groups**.

   **Continue** → **Register**.
4. Привяжите группу к обоим App ID — это можно только после регистрации. В списке
   **Identifiers** нажмите `forum.iqro.app` → у **App Groups** кнопка **Configure** →
   отметьте `group.forum.iqro.app` → **Continue** → **Assign** → **Done** → **Save** (если
   спросит — **Confirm**). То же для `forum.iqro.app.PrayerTimesHomeWidget`.

Больше ничего не включайте: push, «Войти с Apple» и остальное не нужны. Исключение — если
по Р4 оставляете США с проверкой возраста: тогда спросите в чате до шага 4, какую ещё
возможность отметить (Declared Age Range).

Все три возможности отметьте до шага 4: профиль без Time Sensitive Notifications не подпишет
сборку, в которой есть это право. Любое изменение App ID, в том числе новая возможность,
делает его профили из шага 4 недействительными — их перевыпускают и заново кладут в GitHub,
около 15 минут.

## 4. Сертификат и два профиля

Сертификат делается на Mac, в «Связке ключей». Xcode не нужен. Пункты 1–6 ниже делайте на
одном и том же Mac: секретная половина ключа остаётся в его «Связке ключей».

**Запрос сертификата**

1. ⌘ + пробел → «Связка ключей» → Return. (В «Утилитах» её на macOS 26 нет.)
2. Меню **Связка ключей** → **Ассистент сертификации** → **Запросить сертификат у бюро
   сертификации…**
3. **E-mail пользователя** — почта вашего Apple Account, **Общее имя** — `IQRO`,
   **Адрес e-mail БС** оставьте пустым, **Запрос** — **Сохранен на диске** →
   **Продолжить** → сохраните на Рабочий стол.

**Сертификат**

4. https://developer.apple.com/account/resources/certificates → **+** → **Apple
   Distribution** → **Continue** → **Choose File** → файл с Рабочего стола → **Continue** →
   **Download**.
5. Дважды щёлкните скачанный `distribution.cer`: он встанет в «Связку ключей».
6. «Связка ключей» → вверху **Мои сертификаты** → выделите «Apple Distribution: <ваше
   имя> (<Team ID>)» → меню **Файл** → **Экспортировать объекты…** → имя
   `iqro-distribution`, место — Рабочий стол, **Формат файла** — **Обмен персональной
   информацией (.p12)** → **Сохранить** → придумайте пароль. Mac может спросить свой
   пароль — это нормально. Файл и пароль — в заметку «IQRO Apple».

**Два профиля**

7. https://developer.apple.com/account/resources/profiles → **+** → в разделе
   **Distribution** выберите **App Store Connect** → **Continue** → App ID `forum.iqro.app` →
   **Continue** → ваш сертификат → **Continue** → Provisioning Profile Name:
   `IQRO App Store` → **Generate** → **Download**.
8. Ещё раз то же для `forum.iqro.app.PrayerTimesHomeWidget`, имя `IQRO Widget App Store`.

Имена профилей вводите точно так, с пробелами: по ним их ищет проект.

Сертификат и профили действуют около года; точная дата видна в портале у каждого —
запишите её в заметку и поставьте напоминание за месяц. Сертификат не продлевается:
за месяц до срока сделайте новый (пункты 1–6), затем у каждого профиля **Edit** → отметьте

`IOS_PROFILE_WIDGET_BASE64`. Приложение в App Store от истечения не страдает, но новую

## 5. Ключ App Store Connect API

С ним GitHub загружает сборку в App Store Connect.

1. https://appstoreconnect.apple.com → **Users and Access** → вкладка **Integrations**
   (откроется **App Store Connect API**).
2. Первый раз — **Request Access** → отметьте согласие с условиями → **Submit**. Apple
   рассматривает заявку не сразу и сроков не называет, поэтому сделайте это сразу после
   вступления (раздел 2). Дальше — когда доступ одобрят.
3. Вкладка **Team Keys** → **Generate API Key** (для первого ключа; потом — **+**):
   - имя: `IQRO CI`;
   - **Access**: **Admin**.

   **Generate**. Имя и роль потом не поменять — только сделать новый ключ.
4. **Download API Key** — файл `AuthKey_<Key ID>.p8`. Скачать можно **только один раз**,
   у Apple копии нет. Сразу в заметку «IQRO Apple».
5. **Key ID** — в строке ключа (наведите → **Copy Key ID**). **Issuer ID** — вверху
   страницы (**Copy**).

Почему Admin. По таблице ролей Apple загружать сборки без условий может только Admin.
App Manager — лишь с доступом к сертификатам, а у физлица такой доступ есть только у
владельца аккаунта. Справка «Upload builds» App Manager разрешает, но страницы Apple
противоречат друг другу, а Admin загрузит точно.

Ключ Admin сильный: им можно менять пользователей, сертификаты и приложения. Он лежит
только в секретах GitHub и в заблокированной заметке. Если он утёк: **Team Keys** → **Edit** → отметьте ключ →
**Revoke Key** → **Revoke**. Он сразу перестанет работать; сделайте новый и замените
в GitHub все три значения ключа.

## 8. Первая сборка и TestFlight

Сборку запускают, когда в `main` слиты все правки для iPhone и вы сказали «собирай».
Обычно запускает Claude по вашему слову; можно и самому:

1. GitHub → **Actions** → **iOS release** → **Run workflow** → ветка `main`. Два поля:
   - **build_name** — версия для людей, как у следующего Android, например `1.0.17` (Р7);
   - **build_number** — номер сборки; внутри одной версии каждый следующий больше.
     Значение подскажет Claude.

   → **Run workflow**. (Поле **build_name** добавляет сессия ios-native; до её правки
   сборка ушла бы с версией 1.0.10.)
2. Сборка идёт 15–25 минут. Подписанная сборка ещё ни разу не запускалась, поэтому первый
   запуск может потребовать одной-двух правок. Если она упала, пришлите в чат ссылку на
   запуск.
3. App Store Connect → **Apps** → IQRO → вкладка **TestFlight** → **Build Uploads**. Сначала
   у загрузки статус **Processing**, потом **Complete**; о каждом шаге Apple пишет письмо.
   Сроков Apple не называет; если **Processing** дольше суток — скажите в чат.
4. Один раз создайте группу внутреннего теста: там же **+** рядом с **Internal Testing** →
   имя `IQRO` → отметьте **Enable automatic distribution** (новые сборки будут приходить
   сами) → **Create**. Затем в группе **Invite Testers** → отметьте себя → **Add**. Проверка
   Apple для внутреннего теста не нужна; в группе может быть до 100 человек из вашей
   команды App Store Connect.
5. Если сборки нет в группе, добавьте вручную: группа → **Add Builds** → сборка → **Next** →
   **Add**. Готовая к тесту сборка — в статусе **Ready to Submit** или **Testing**.
6. На iPhone поставьте из App Store приложение **TestFlight** — ему нужна iOS 16 или новее
   (так на его странице в App Store и на testflight.apple.com, проверено 27.11.2026). Откройте
   письмо-приглашение на этом iPhone → **Просмотреть в TestFlight** (в английском письме —
   View in TestFlight) → **Принять** → **Установить**. Режим разработчика не нужен.
7. Пройдите [список проверки](ios-testflight-checklist.md).

Если после загрузки придёт письмо Apple с кодом вида ITMS-91053 (не хватает строки
в манифесте приватности), перешлите его в чат и посмотрите статус в **Build Uploads**:
**Failed** или сборки нет в TestFlight — нужна новая сборка с исправленным манифестом (после
**Failed** номер сборки можно взять тот же); **Complete** — тестировать можно, манифест
исправим к следующей.

Сборка в TestFlight живёт 90 дней. Это та же сборка, что уйдёт на проверку в App Store:
пересобирать её после проверки не нужно.

**Внешний тест — по желанию**, например чтобы IQRO проверил кто-то с iPad: до 10 000 человек
по почте или общей ссылке. Нужно заполнить **TestFlight** → **Test Information**: описание
беты (**Beta App Description**), почту для отзывов (**Feedback Email**) и вход для
проверяющего, как в разделе 9. Первая сборка для внешних тестировщиков проходит проверку
Apple.

### Шифрование (экспорт)

Ответ уже записан в сборке: несвободного шифрования нет (`ITSAppUsesNonExemptEncryption =
false`), приложение шифрует только соединение HTTPS, а его главная задача — не шифрование.
Поэтому App Store Connect анкету о шифровании не показывает ни при первой сборке, ни потом.

Тонкость. Как типичный пример освобождённого шифрования Apple называет HTTPS средствами
самой iOS. Часть запросов IQRO идёт через стандартную TLS-библиотеку внутри Flutter. Для
такого случая таблица Apple просит французскую декларацию о шифровании, если приложение
продаётся во Франции; годовой отчёт в США для массовых приложений с 2021 года не нужен.
Большинство Flutter-приложений публикуется так же, без деклараций. Если App Store Connect
всё же покажет анкету, ничего не отвечайте — пришлите снимок вопроса в чат.

### App Review Information

На странице версии, внизу.

   Regions** → **Next** → отметьте все, кроме **China mainland** (и США, если решите их
   убрать) → **Next** → **Confirm**. В материковом Китае нужны номер ICP и отдельное
   разрешение для религиозного содержания — их у проекта нет. Позже страны меняют там же:
   **Manage** → **Manage Availability**. Изменение действует сразу, всем видно в течение
   суток. Галочка внизу списка добавляет будущие страны App Store сама — ставьте по желанию.
3. 🔶 **США** — решаете вы. Убрать один штат нельзя, только страну целиком.
   - **Оставить.** В Техасе закон SB 2420 действует для новых аккаунтов Apple с 04.06.2026:
     разработчик должен проверять возрастную группу пользователя по данным App Store и
     спрашивать согласие родителей при значимых изменениях. Apple пишет: в таких регионах
     вы обязаны проверять возраст, по закону — к юристу. Проверку приложения в App Store
     это не меняет. Нужен код с Declared Age Range от Apple: около 3–4 дней на iPhone и
     1–2 дня на Android, чтобы было одинаково. Для этого у приложения появится ещё одно
     право (Declared Age Range); вероятно, его придётся отметить и у App ID и перевыпустить
     профили. Юту и Луизиану Apple называет с мая и июля 2026 года; по сведениям юристов,
     их законы перенесены на май и июль 2027-го, а с 01.01.2027 добавляются Калифорния
     и Алабама. Без кода — правовой риск. Android 1.0.16 в Google Play уже в том же
     положении, поэтому решать лучше сразу для обеих платформ.
   - **Убрать.** Кода не нужно: снимите **United States** в списке стран. Вернуть можно
     в любой момент, новая сборка не нужна. Минус: человек с американским Apple Account не
     поставит IQRO. Начать без США проще, чем убрать их потом: кто успел поставить, тот
     продолжит получать обновления.
4. 🔶 **ЕС, статус трейдера (DSA)** — один на весь аккаунт: App Store Connect →
   **Business** → **Agreements** → раздел **Compliance** → у **Digital Services Act**
   кнопка **Complete Compliance Requirements**. Указать нужно, даже если ЕС убрать; если не
   указать заранее, Apple спросит при отправке приложения.
   - **This is not a trader account** (не трейдер) → **Done**. Контакты не публикуются.
     Покупателям в ЕС сообщат, что права потребителя на договор с вами не
     распространяются. Apple пишет: кто сделал приложение как хобби, без цели заработка,
     может не считаться трейдером, но решает сам разработчик. Признаки трейдера — доход от
     приложения, реклама, работа в рамках бизнеса.
   - **This is a trader account** (трейдер). На странице IQRO во всех 27 странах ЕС будут
     видны ваши адрес, телефон и почта. Apple проверит почту и телефон кодами и попросит
     документ с именем и адресом. Можно указать абонентский ящик, если приложить документ
     о нём (например, счёт).

   Статус потом можно сменить у приложения: IQRO → **General** → **App Compliance** →
   **Digital Services Act** → **Edit**. Без статуса приложение в ЕС не показывается.
5. **Mac и Apple Vision Pro** — там же снимите две отметки и нажмите **Save**:
   - **iPhone and iPad Apps on Apple Silicon Mac** → **Make this app available**;
   - **iPhone and iPad Apps on Apple Vision Pro** → **Make this app available on Apple
     Vision Pro**.

   Иначе Apple может сама выпустить IQRO и там, а там его никто не проверял. Вернуть можно
   позже.
6. **iPad** — решено: **только iPhone** (Р1). Это не переключатель в App Store Connect:
   семейство устройств задаётся в сборке, его меняет сессия ios-native. На iPad IQRO всё
   равно появится как iPhone-приложение (режим совместимости) — это нормально, исключать
   iPad не нужно. iPad можно добавить позже, а убрать нельзя: Apple не примет обновление,
   которое работает на меньшем числе устройств. Снимки iPad 13″ не нужны; на симуляторе
   iPad мы приложение один раз прогоняем, потому что проверяющий может открыть его там.

## 11. Снимки и отправка на проверку

**Снимки.** Нужны только снимки iPhone 6,9″ (1320×2868): хотя бы один, можно до 10. Если для
языка своих снимков нет, App Store покажет снимки основного языка; мы делаем на всех четырёх.
Обязательным Apple сейчас называет класс «iPhone с Dynamic Island» (1206×2622); снимки 6,9″
— его крупный вариант, Apple уменьшает их сама — это проверим при загрузке. Снимки iPad 13″
не нужны: выпуск только для iPhone. Снимки Google Play не подходят: другой размер и строка
состояния Android. Новые снимки на 4 языках делает сессия ios-native на симуляторе, вы
утверждаете.

**Тексты.** Описание и ключевые слова — из [app-store-listing.md](app-store-listing.md).
Перед отправкой их обновят: в описании нет новых функций, а «статистика — только с вашего
согласия» неточна (обезличенные суммы уходят всегда, см. App Privacy). У первой версии
«What's New» не заполняется. Для следующих заметки Android берут без того, что есть только
на Android: например, проверку букв и огласовок делает только Android.

**Страница версии** (App Store Connect → IQRO → версия iOS):

1. Языки: основной — русский; добавьте **English (U.S.)**, **Arabic** и **Turkish**
   (меню языка вверху справа).
2. На каждом языке вставьте из [app-store-listing.md](app-store-listing.md) описание,
   ключевые слова и Promotional Text; **Support URL** — `https://iqro.forum/ru/contacts`
   (на других языках `/en/`, `/ar/`, `/tr/`), **Marketing URL** — `https://iqro.forum`.
3. Перетащите снимки в раздел снимков iPhone. Где они будут лежать, скажет сессия ios-native.
4. **Copyright** — `2026 Mr.Fulani (Iqro-Forum project)`.

**Отправка:**

1. App Store Connect → IQRO → версия iOS → в **Build** выберите сборку из TestFlight.
2. Проверьте, что заполнены: снимки и тексты на 4 языках, URL, Copyright, App Privacy, Age
   Rating, App Review Information, цена и страны, статус трейдера.
3. В разделе **App Store Version Release** выберите **Manually release this version**: так
   iPhone и Android выйдут в один день.
4. **Add for Review** → **Submit for Review**. Статус станет **In Review**.
5. После одобрения статус — **Pending Developer Release**. В день выпуска: версия →
   **Release This Version** → подтвердить. В App Store она появится в течение суток.

Apple обычно отвечает за 1–2 дня: половину заявок проверяет меньше чем за сутки, 90 % —
меньше чем за двое. Заложите один-два круга: первые отказы чаще всего по правилу 2.1
(сбои, заглушки, нет входа для проверяющего) и по приватности.

## 12. Отчёт о сбое без Xcode

Если IQRO на iPhone закрылось само:

1. **Сразу в TestFlight.** После сбоя появится окно с предложением отправить отчёт
   разработчику. Нажмите **Поделиться**, напишите, что делали, → **Отправить**. Отчёт придёт в App
   Store Connect → IQRO → **TestFlight** → **Feedback** → **Crashes**. Там запись скачивается
   архивом (значок загрузки справа вверху) в течение 120 дней — пришлите архив в чат. Туда
   попадают только отчёты, которые отправили этой кнопкой.
2. **Если окна не было** — отчёт лежит на самом iPhone: **Настройки** →
   **Конфиденциальность и безопасность** → **Аналитика и улучшения** → **Данные Аналитики**.
   Найдите файл, который начинается с `Runner` и датой сбоя (так в сборке называется IQRO;
   у виджета — `PrayerTimesHomeWidget`, при нехватке памяти — `JetsamEvent`), откройте →
   **Поделиться** → AirDrop на Mac или «Почта». Пришлите файл в чат.
3. **Зависло, но не закрылось** — отчёта о сбое не будет. Сделайте снимок экрана →
   миниатюра слева внизу (если снимок сразу открылся на весь экран, пропустите) → **Готово**
   → **Поделиться отзывом о бета-версии** → опишите → **Отправить**. Или в TestFlight
   откройте IQRO → **Отправить отзыв о бета-версии**.
4. **Живой журнал**, если попрошу: подключите iPhone к Mac кабелем, на iPhone нажмите
   «Доверять», на Mac откройте «Консоль» (Finder → «Переход» → «Утилиты»), слева выберите
   iPhone → **Начать**. Xcode для этого не нужен.

Символы для расшифровки отчётов каждая сборка отправляет в App Store Connect и кладёт
артефактом в GitHub, где он хранится 30 дней. Поэтому файл сбоя с iPhone лучше присылать
сразу.

## 13. Порядок выпуска

Один выпуск, без промежуточных сборок.

1. Сессии доделывают правки для iPhone. Каждую проверяет автопроверка на симуляторах
   iPhone и iPad в GitHub — с видео.
2. Слияние в `main` — по вашему слову. Workflow сборки запускается только из `main`.
3. Вы говорите «собирай»: одна сборка в TestFlight, номер версии как у следующего Android.
4. Вы проходите [список проверки](ios-testflight-checklist.md) и проверку чтения вслух.
5. Если что-то видно только на iPhone — один круг исправлений и одна новая сборка.
6. «Всё хорошо» — эта же сборка уходит на проверку Apple, а Android — в Google Play.
7. После одобрения обеих — выпуск в один день.

Если нужна правка после проверки Apple, это новая сборка с новым номером.

## 14. Для разработчика

**Как устроена сборка.** [`.github/workflows/ios-release.yml`](../../.github/workflows/ios-release.yml):
только вручную и только из `main`, `macos-15`, Xcode 26.3, Flutter 3.41.4, CocoaPods из
`Gemfile.lock`.

1. Проверяет переменную `APPLE_TEAM_ID` и 7 секретов, иначе останавливается.
2. Кладёт сертификат во временную связку ключей, профили — в папку Xcode, ключ API — во
   временный файл; в конце всё удаляет, даже при ошибке.
3. `flutter build ios --release --config-only` с `APP_ENV=production`,
   `API_BASE_URL=https://iqro.forum`, `config/firebase.json` и, если задан, `SENTRY_DSN`.
4. `xcodebuild archive` с `DEVELOPMENT_TEAM` из `APPLE_TEAM_ID`; Release подписывается
   вручную: `Apple Distribution`, профили `IQRO App Store` и `IQRO Widget App Store`.
5. `xcodebuild -exportArchive` с [`ios/ExportOptions.plist`](../../clients/iqro_mobile/ios/ExportOptions.plist)
   (`app-store-connect`, `destination = upload`) и ключом API: сборка сразу уходит в App Store
   Connect вместе с символами отладки.
6. dSYM — артефактом `iqro-ios-dsyms` на 30 дней. Для сборки, ушедшей в App Store, архив
   сохраняют отдельно и надолго (например, прикладывают к GitHub Release выпуска): у
   публичного репозитория артефакт живёт не больше 90 дней.

На `main` у workflow пока одно поле — `build_number`, а версию он берёт из `pubspec.yaml`
(`1.0.10`). Сессия ios-native добавляет обязательное поле `build_name` (передаётся во
`flutter build ios --build-name`, `pubspec.yaml` не меняется — как у Android). Внутри одной
версии номер сборки должен расти.
Отладочная конфигурация подписывается автоматически, обычный CI собирает Release без подписи.

**Почему ручная подпись.** При ручной подписи облачная подпись Apple не используется, а
автоматическая подпись при архивации берёт профиль разработки, которому нужно
зарегистрированное устройство. Ручная подпись предсказуема. `-allowProvisioningUpdates` при
экспорте всё равно нужен: с ключом API xcodebuild обращается к сайту Apple и при ручной
подписи. fastlane, Xcode Cloud и Codemagic не нужны: раннеры GitHub для публичного
репозитория бесплатны. Если первый запуск упадёт, чаще всего виновато имя профиля или
профиль, созданный с другим сертификатом.

**Time Sensitive.** Ключ `com.apple.developer.usernotifications.time-sensitive` в
`Runner.entitlements` добавляют только после того, как профиль с этой возможностью окажется
в секретах: иначе подписанная сборка упадёт. Имя ключа Apple в справочнике прав не приводит
(его дают Expo и форумы), поэтому сверить его с разделом Enabled Capabilities скачанного
профиля. Уровень уведомлений (`interruptionLevel`) задаёт ios-audio-adhan.

**Вход через Google и правило 4.8.** На iPhone кнопки Google нет, вход — только
собственный, по коду из письма. Правило 4.8 делает исключение для приложений, которые
«exclusively uses your company's own account setup and sign-in systems», поэтому «Войти
с Apple» не нужен. Если включать Google на iOS, понадобятся сразу «Войти с Apple» (сервер,
приложение, сайт), iOS-клиент OAuth в Google Cloud и `GIDClientID` в Info.plist — 3–5 дней
работы плюс шаги владельца у App ID. Кто вошёл через Google на Android или сайте, на iPhone
войдёт кодом на ту же почту и попадёт в тот же аккаунт.

**После первого выпуска.**

- С апреля 2027 Apple принимает только сборки с iOS 27 SDK. Xcode 27 работает на macOS
  26.6+, поэтому CI переходит на образ `xcode-27`. Flutter при этом, судя по его списку
  изменений, придётся поднять минимум до 3.44.8 — это затронет и Android.
- Сборкам с iOS 27.1 SDK и новее с апреля 2027 нужны и снимки iPhone Duo.
- CocoaPods trunk с 02.12.2026 не принимает новые pod; опубликованные остаются, сборки
  не ломаются. Firebase закреплён поэтому.
- Подсказка об обновлении на iPhone и значок App Store на сайте — после выхода.
