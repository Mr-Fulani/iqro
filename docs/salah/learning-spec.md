# Обучение намазу (salah) — техническое задание v2

Версия 2 пересматривает исходное ТЗ («Интерактивный модуль обучения намазу», v1.0) под существующую кодовую базу IQRO. Источник разбора — экспертный отзыв от 18.10.2026.

Цель модуля: новичок с нуля учится подготовке к молитве, омовению и пяти обязательным молитвам по ханбалитскому мазхабу. Модуль одинаково работает в приложении (Flutter) и на сайте (Next.js) поверх одного бэкенда.

## 1. Решения владельца продукта (интервью 18.10.2026)

| Вопрос | Решение |
|---|---|
| Методология | Ханбалитский мазхаб, по «Умдат аль-фикх» Ибн Кудамы. Других вариантов в первой версии нет. |
| Мужской и женский вариант | Только мужской в первой версии. Схема данных допускает варианты, контент их пока не содержит. |
| Религиозная проверка | Владелец продукта подписывает версию курса в админке. Без подписи версия не публикуется. |
| Иллюстрации | WebP, генерация через kie: единый спокойный стиль, без лица, одинаковые одежда и ракурс. Rive позже. |
| Место в интерфейсе | Плитка «Обучение намазу» в «Ещё», ссылка с экрана времени намаза. На сайте раздел `/{locale}/salah`. |
| Объём первой версии | Основы, вуду, пять фард-молитв, витр, саджда сахв, молитва за имамом, сунны-раватиб. |
| Аудио формул | То, что уже есть: ду'а «Хисн аль-Муслим» с их записями, Фатиха и суры из аудиокаталога Корана. Короткие формулы без записи загружаются через админку. |
| Языки | Сразу 4: ru, en, ar, tr. Тексты уроков пишутся на всех четырёх, формулы берутся из уже переведённых ду'а. |
| Бэкенд | Один для сайта и приложения. |

## 2. Принципы

1. **Клиенты только отрисовывают.** Порядок шагов, правила ракаатов, тексты и формулы приходят с сервера. В коде клиентов нет `if (prayer == fajr)`.
2. **Последовательности собираются на сервере.** Правила ракаатов (вслух или про себя, сура после Фатихи, средний ташаххуд, кунут) разворачиваются при публикации в линейные шаги. Логика пишется один раз, на Python, и проверяется snapshot-тестами в CI бэкенда.
3. **Формулы не копируются.** Текст ташаххуда, тасбиха в руку' и других формул — ссылка на запись «Хисн аль-Муслим» или на аяты Корана. При публикации ссылка разрешается в текст, перевод, транслитерацию и аудио.
4. **Версии неизменяемы.** Шаблон домена ду'а: черновик → опубликовано → отозвано. `active_version` указывает на опубликованную версию, опубликованное в админке только читается.
5. **Контент как код.** Курс хранится в репозитории как JSON-снимок (`salah/data/*.json`) и импортируется командой, как `import_dua_catalog`. История правок и откат идут через git и pull request.
6. **Производительность.** Один документ курса на язык, заранее скомпилированный и сохранённый в БД. Сервер отдаёт его с ETag и 304. Клиенты кэшируют документ, картинки WebP до 60 КБ, следующий шаг подгружается заранее.
7. **Паритет.** Приложение и сайт отрисовывают один и тот же документ. Отличаются только офлайн-пакеты (только в приложении) и haptic.
8. **Без геймификации.** Нет монет, рейтингов и оценки намаза. Прогресс выглядит как «7 из 12 уроков».

## 3. Чего не будет из исходного ТЗ и почему

| Исходное ТЗ | Решение |
|---|---|
| Drift для локальной БД | Не добавляем. Прогресс хранится в `app_state` существующей `LocalDatabase`, документ курса в её кэше. |
| Отдельный `PrayerAudioController` | Не делаем. Используем общий `IqroAudioEngine` (`loadStandalone` и смежные методы), второй плеер сломал бы мини-плеер и экран блокировки. |
| Семь статусов на каждую строку контента | Заменено подписью на версию курса: проверяющий, дата, примечание. |
| Отдельная CMS с редактором уроков | Не делаем. Контент ведётся JSON-снимком в git, в админке видны версии, предпросмотр, подпись и публикация. |
| `PrayerSequenceEngine` в клиенте | Перенесён на сервер как компилятор. |
| `/learn/prayer/...` | Маршрут `/salah` (`/prayer` занят временем намаза). |
| Rive, запись голоса, караоке по словам, проверка произношения, камера | Не входят в первую версию. В архитектуру заранее не закладываются. |
| Отдельный SRS для формул | Позже, через домен заучивания. |
| Аналитика событий | Нет: в IQRO нет аналитики, решение отложено. |

## 4. Модель данных (бэкенд, Django app `salah`)

```
SalahCourse               slug (unique), active_version → SalahCourseVersion (PROTECT, null)
SalahCourseVersion        course, version, schema_version, methodology ("hanbali"),
                          source_title ("Умдат аль-фикх"), checksum_sha256 (снимок),
                          status draft|published|withdrawn, published_at,
                          reviewed_by (User, null), reviewed_at, review_note
                          — публикация разрешена, только если reviewed_by заполнен
SalahCompiledDocument     version, language (ru|en|ar|tr), payload (JSON),
                          checksum_sha256, bytes — unique (version, language)
SalahMediaAsset           version, key ("position-ruku"), object_key (неизменяемый),
                          content_type, width, height, bytes, sha256, alt (по языкам)
```

Снимок курса (`salah/data/hanbali-umdah-v1.json`), формат schema_version 1:

- `course`: slug, version, methodology, source_title.
- `formulas[]`: формулы.
  - `{id, source: {kind: "dua", collection, source_number}}`
  - `{id, source: {kind: "quran", surah, ayah_from, ayah_to}}`
  - `{id, source: {kind: "inline", arabic, translations{lang: {meaning, transliteration}}, audio_media?}}` — только для коротких формул, которых нет в «Хисн аль-Муслим»: такбир, «сами'а Ллаху лиман хамидах», таслим.
- `media[]`: `{key, file, alt{lang}}`. Файл загружается командой импорта в объектное хранилище под неизменяемым ключом.
- `sections[]`: `{slug, title{lang}, lessons[]}`.
- `lessons[]`: урок.
  - `{slug, kind: article|steps|prayer, title{lang}, summary{lang}, minutes, steps[]|prayer}`.
- Шаг: `{slug, kind: action|recitation|info, position?, ruling?: rukn|wajib|sunnah, title{lang}, instruction{lang}, details?{lang}, media?, formulas[], repeat?}`.
- `prayer`: `{code, kind: fard|witr|sunnah, rakats, rakat_rules[], template}`.
  - `rakat_rules[]`: `{rakat, recitation: jahr|sirr, surah_after_fatiha: bool, sitting: none|middle_tashahhud|final_tashahhud, qunut: bool}`.
  - `template`: шаблон ракаата, шаги с условиями `when: {first_rakat, surah_after_fatiha, sitting, qunut}`.

Пример снимка: `docs/salah/course-snapshot.example.json`. Шаблон молитвы (`templates[]`) — это шаги одного ракаата. Условия `when` задают, когда шаг попадает в ракаат:

- `first_rakat: true` — только в первом ракаате;
- `surah_after_fatiha: true` — только если после Фатихи читается сура;
- `sitting: [...]` — только при таком сидении;
- `qunut: true` — только если есть кунут.

У скомпилированного шага slug `<урок>.r<ракаат>.<шаг шаблона>`, например `fajr.r1.ruku`. У шагов уроков, которые не являются молитвой, slug `<урок>.<шаг>`.

Компилятор (`salah/compiler.py`, чистые функции) на публикации:

1. Проверяет снимок: уникальные slug, существующие формулы и медиа, все 4 языка, нет пустых шагов. Это проверки §84 исходного ТЗ.
2. Разрешает формулы:
   - ду'а: активная версия «Хисн аль-Муслим», текст, перевод и транслитерация на нужном языке, аудио;
   - Коран: текст аятов из опубликованного издания, аудио суры по умолчанию и таймкоды аятов.
3. Разворачивает молитвы по `rakat_rules` в линейные шаги с номером ракаата.
4. Сохраняет по `SalahCompiledDocument` на каждый язык и считает checksum.

Snapshot-тесты (`tests/test_salah_sequences.py`) фиксируют полный порядок шагов каждой молитвы. Любая правка контента, которая меняет порядок, ломает тест и требует осознанного обновления снимка.

## 5. API (один для сайта и приложения)

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/v1/salah/courses` | Список курсов: slug, version, methodology, languages, published_at. |
| GET | `/api/v1/salah/courses/{slug}?language=ru` | Скомпилированный документ (раздел 6). ETag и 304. Неизвестный язык даёт 400. |
| GET | `/api/v1/salah/courses/{slug}/offline-manifest?language=ru` | Манифест офлайн-пакета `package_type: "salah_course"`: документ и все WebP с sha256 и размером. |

Кэш: `PublicReadOnlyViewMixin` (`Cache-Control: public, max-age=300, stale-while-revalidate=86400`, ETag по содержимому). Ответ — готовый JSON из `SalahCompiledDocument.payload`, без сборки на каждый запрос.

Публикация и отзыв ставят событие ревалидации `salah.course.changed {action, course, version}`. Сайт сбрасывает теги `salah:*`.

## 6. Контракт документа курса

Полный пример: `docs/salah/course-document.example.json`. Клиенты пишутся строго по нему, бэкенд проверяет совместимость контрактным тестом.

```
{
  "schema_version": 1,
  "course": {slug, version, methodology, source_title, language,
             reviewed_by, reviewed_at, published_at, checksum_sha256},
  "sections": [{slug, title, lessons: [lesson_slug]}],
  "lessons": [{
    slug, kind: "article"|"steps"|"prayer", title, summary, minutes,
    prayer?: {code, kind: "fard"|"witr"|"sunnah", rakats},
    steps: [{
      slug,                     // стабильный id: "fajr.r1.ruku"
      kind: "action"|"recitation"|"info",
      position?: "takbir"|"qiyam"|"ruku"|"itidal"|"sujud"|"jalsa"|"tashahhud"|"taslim"|…,
      ruling?: "rukn"|"wajib"|"sunnah",
      rakat?: 1..4,             // только для молитв
      title, instruction, details?,
      media?: media_key,
      formulas: [formula_id],
      repeat?: n
    }]
  }],
  "formulas": {id: {arabic, transliteration?, translation, repetitions,
                    audio?: {url, start_ms?, end_ms?, segments?: [{ayah, start_ms, end_ms}]},
                    source: {kind: "dua", collection, source_number}
                          | {kind: "quran", surah, ayah_from, ayah_to}
                          | {kind: "inline"}}},
  "media": {key: {url, width, height, bytes, sha256, alt}}
}
```

Все тексты уже на языке запроса. Клиент не выбирает перевод, не собирает последовательность и не знает фикха.

## 7. Клиенты

### 7.1 Приложение (`clients/iqro_mobile/lib/features/salah`)

- **Структура.** `SalahRepository` хранит документ в кэше `LocalDatabase` под ключом `salah:<slug>:<lang>:<version>`. Перед использованием кэша сверяет версию, как это делает `DuaRepository`. Провайдеры в `app/providers.dart`.
- **Маршруты.** `/salah` (главная модуля), `/salah/lesson/:slug`, `/salah/lesson/:slug/step/:step`. Обёртка `AudioNavigationBoundary(section: salah)`, в enum добавляется новое значение.
- **Точки входа.** Плитка в `MoreToolsGrid`, ссылка с `PrayerScreen`. Deep link `iqro.forum/{locale}/salah/...` такой же, как у сайта.
- **Step Player.**
  - Шаги листаются в `PageView`, внизу кнопки «Назад» и «Далее».
  - Для VoiceOver и TalkBack есть `CustomSemanticsAction` «следующий шаг» и «предыдущий шаг». В RTL направление свайпа зеркалится.
  - Картинка показана с фиксированными пропорциями. Картинка следующего шага подгружается заранее (`precacheImage`).
  - Формулы рисуются общей карточкой: арабский текст, транслитерация, перевод, аудио, счётчик повторений. `_RepetitionCounter` и разбор арабского текста выносятся из `dua_screen.dart` в общий виджет.
- **Молитва.** Тот же плеер. Сверху точки ракаатов и «Шаг N из M».
- **Режимы.** «Обучение» (полный текст) и «Практика» (только картинка, арабский текст и аудио). «Без подсказок» добавляется флагом позже.
- **Аудио.** `loadStandalone` / `toggleStandalone` / `setStandaloneSpeed`. Повтор N раз с паузой добавляется в контроллер общим методом по образцу `MemorizationAudioLoop` сайта.
- **Прогресс.** Хранится локально в `app_state` (`salah.progress.<course>`): статус урока, `step_slug`, `content_version`. Если `step_slug` пропал в новой версии, урок открывается с начала. Пройденный урок не откатывается.
- **Офлайн.** Документ лежит в кэше. Картинки скачиваются офлайн-пакетом `salah_course` через существующий механизм офлайн-пакетов. Тип нужно добавить в `_knownPackageTypes`, `_packageDirectory` и `_protectedKeyPrefixes`. Аудио в первой версии потоковое.

### 7.2 Сайт (`services/web/app/[locale]/salah`)

- **Маршруты.** `/{locale}/salah` (разделы и уроки) и `/{locale}/salah/[lesson]` (шаги). Серверная отрисовка с ISR: `fetchPublishedJson` с тегами `salah:course:<slug>` и `salah:locale:<l>`, `revalidate = 3600`.
- **SEO.** Каждый урок индексируется: заголовок, шаги и арабский текст есть в HTML.
- **Step Player.** Клиентский компонент поверх того же документа: кнопки, клавиши ←/→ (в RTL наоборот), аудио через `claimAudioFocus` и `registerAudioPlayer`, как в `DuaEntryList`.
- **Прогресс.** Хранится в `localStorage` в том же формате, что и в приложении.
- **Навигация.** Пункт «Обучение намазу» в «Ещё» мобильной навигации и в меню шапки. Имя маршрута `/salah` не пересекается с `/prayer` при проверке через `startsWith`.
- **Ревалидация.** Событие `salah.course.changed` в `lib/content-revalidation.ts`.

## 8. Синхронизация прогресса (этап 2)

Новый тип синхронизации `salah_progress` в `reading` sync. Для этого нужно добавить:

- значение в enum и миграцию;
- проверку в `SyncOperationInputSerializer`;
- обработку в `_apply_sync_operation`;
- фазу полной пересинхронизации;
- перенос гостевых данных при входе в `accounts/merge.py`;
- клиентские части в `sync_store.dart`.

Конфликты решаются так: побеждает более поздняя ревизия, но `completed` не откатывается.

## 9. Доступность и производительность

**Доступность:**
- семантика на всех кнопках;
- кнопки «Назад» и «Далее» всегда видны, жесты не единственный способ управления;
- у каждой картинки есть текст `alt`;
- арабский текст масштабируется настройкой размера шрифта ридера;
- крупный системный шрифт не ломает вёрстку;
- аудио не единственный канал информации.

**Производительность:**
- документ курса на язык не больше 150 КБ в JSON (около 25 КБ в gzip);
- картинка не больше 60 КБ WebP при ширине 720 px;
- переход между шагами без сетевых запросов;
- на сайте документ рендерится на сервере и кэшируется ISR.

## 11. Готовность первой версии

Пользователь в приложении и на сайте может:

1. открыть «Обучение намазу» из «Ещё» или с экрана времени намаза;
2. пройти основы и вуду по шагам с иллюстрациями;
3. пройти каждую из пяти фард-молитв, витр и сунны-раватиб пошагово, по ракаатам;
4. открыть уроки «Саджда сахв» и «Молитва за имамом»;
5. прослушать каждую формулу и посчитать повторения;
6. переключать транскрипцию и перевод;
7. вернуться к незавершённому уроку на том же шаге;
8. в приложении пользоваться курсом без интернета после загрузки, кроме аудио;
9. пользоваться модулем на ru, en, ar и tr, с RTL для арабского;
10. пользоваться модулем с VoiceOver или TalkBack и крупным шрифтом.

Изменения контента выходят без релиза приложения: импорт новой версии, подпись, публикация.
