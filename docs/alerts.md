# Уведомления админу в Telegram

Бот пишет в Telegram-группу владельца, чтобы быстро реагировать на обращения,
выпуски на подписи и поломки. Без настройки уведомления выключены, всё остальное
работает как прежде.

## Что приходит

| Событие | Когда |
| --- | --- |
| 📩 Новое обращение | сразу; категория, тема, текст до 300 знаков, ссылка в админку |
| 🕌 Новое обращение · Религиозное содержание | то же для категории `religious_content` |
| 🟡 Выпуск курса ждёт подписи | автор подготовил выпуск тематического курса |
| 🟡 Таджвид / Обучение намазу: новая версия ждёт подписи | создан черновик новой версии |
| 🟢 Опубликовано, ⚪️ скрыто, ↩️ возвращён прежний выпуск | после публикации, скрытия, показа и отката |
| 🎬 Не удалось загрузить видео или озвучку | загрузка в теме курса отклонена или хранилище недоступно |
| 🔴 Ошибка сервера · backend / worker / beat | любая запись уровня ERROR; одинаковая ошибка — не чаще раза в 30 минут, через 30 минут приходит «повторилась ещё N раз» |
| 🔴 Celery beat не отвечает | beat молчит 5 минут; когда вернётся — ✅ |
| 🔴 Бэкап не прошёл или устарел, сайт не отвечает | проверка на сервере раз в 5 минут; при долгой поломке напоминание раз в 6 часов, по исправлении — ✅ |

Защита от шквала: не больше 20 сообщений за 10 минут, остальные сворачиваются в одно
«⚠️ И ещё N уведомлений». Токен бота нигде не печатается и не попадает в логи и Sentry.

## 1. Создать бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Имя — например, `IQRO Alerts`; логин — уникальный, заканчивается на `bot`,
   например `iqro_alerts_bot`.
3. BotFather пришлёт токен вида `123456789:AA…`. Это пароль бота: не пересылайте его,
   не кладите в Git и в чаты.

## 2. Добавить бота в группу и узнать chat id

1. Создайте группу (или возьмите существующую), добавьте в неё бота.
2. Напишите в группе любое сообщение, например `/start@iqro_alerts_bot`.
3. На своём компьютере откройте в браузере (вместо `<ТОКЕН>` — токен бота):
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
4. Найдите `"chat":{"id":-100…` — это chat id группы, обычно отрицательное число,
   у супергрупп начинается с `-100`.

Если ответ пустой (`"result":[]`), напишите в группе ещё раз и обновите страницу.
Если бот не видит сообщений группы, у BotFather: `/setprivacy` → выбрать бота → `Disable`,
затем удалите бота из группы и добавьте снова.

## 3. Вписать две строки на сервере

На сервере в `/opt/quran/services/backend/.env.production` допишите:

```dotenv
TELEGRAM_BOT_TOKEN=123456789:AA…
TELEGRAM_ALERT_CHAT_ID=-1001234567890
```

Файл читают контейнеры backend, worker и beat, а также проверка бэкапов на самом
сервере (из файла она берёт только эти две строки). Перезапустите контейнеры —
обычная выкладка `make production-up` (с TLS-оверлеем, как всегда).

Проверка:

```bash
docker compose -f compose.production.yaml -f compose.production.tls.yaml exec backend python manage.py send_test_alert
```

В группе появится «✅ Проверка уведомлений IQRO». Если нет — команда напишет причину:
нет переменных, неверный токен или chat id, бот не в группе.

## 4. Проверка бэкапов на сервере

Уведомления о бэкапах и строку «Бэкап базы» на главной админки даёт systemd-таймер
`quran-heartbeat@production` (`ops/monitoring/heartbeat.py`). Он раз в 5 минут
проверяет сайт, `/api/v1/health/ready`, свежесть локального дампа и квитанции
выгрузки, пишет сводку в `/var/lib/iqro-monitor/production/status.json` (её читает
админка) и шлёт в Telegram при смене состояния. Неудачный ночной бэкап сообщает о
себе сразу.

После выкладки этой версии обновите unit-файлы (в heartbeat добавлена папка
состояния):

```bash
sudo sh /opt/quran/ops/systemd/install.sh
sudo systemctl restart quran-heartbeat@production.timer
```

Если таймер ещё не настроен, следуйте `docs/backup-recovery.md`, шаг 7. Адрес
внешнего монитора (Healthchecks) теперь необязателен: можно нажать Enter на обоих
вопросах — тогда сигналы идут только в Telegram.

## 5. UptimeRobot: сайт недоступен извне

Если упал весь сервер, он сам ничего не пришлёт. Это закрывает бесплатный
[UptimeRobot](https://uptimerobot.com) — проверка снаружи раз в 5 минут.

1. Зарегистрируйтесь, в **Integrations** добавьте **Telegram** и следуйте подсказке:
   UptimeRobot даст ссылку на своего бота, его нужно добавить в ту же группу.
   Если Telegram недоступен на вашем тарифе, оставьте уведомления на почту.
2. **Add New Monitor** → тип **HTTP(s)**:
   - Friendly Name: `IQRO сайт`, URL: `https://iqro.forum`, интервал 5 минут;
   - в **Alert Contacts** отметьте Telegram.
3. Второй монитор так же: `IQRO API`, URL `https://iqro.forum/api/v1/health/ready`
   — отвечает 200, когда API, база и Redis в порядке, и 503, когда что-то из них
   недоступно; UptimeRobot считает 503 падением.

Бесплатный тариф UptimeRobot — 5 минут между проверками; по их правилам он для
некоммерческого использования.

## Как это устроено

- `services/backend/src/quran_backend/modules/alerts/` — отправка через Celery
  с повторами, лимит, дедупликация ошибок, слежение за beat, команда
  `send_test_alert`.
- Обработчик логов `TelegramAlertHandler` подключён в `LOGGING`; в процессах Celery
  `apps.py` добавляет его к корневому логгеру после настройки логов Celery.
- Beat проверяется по его singleton-аренде в Redis (`CELERY_BEAT_LOCK_KEY`):
  поток в каждом worker смотрит раз в минуту.
- `ops/monitoring/alerts.py` — то же для проверок на самом сервере, только
  стандартная библиотека Python, работает и когда Docker лежит.
- Выключить: удалить или очистить две строки в `.env.production` и перезапустить
  контейнеры.
