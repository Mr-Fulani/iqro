# PageSpeed главной страницы, 02.11.2026

Разбор отчёта PageSpeed Insights для `https://iqro.forum/en` (Lighthouse 13.6, мобильный профиль
Moto G Power, медленный 4G) и что с ним сделано. Открытые пункты — в
[tech-debt.md](tech-debt.md): 1.8 и раздел 2, «Сайт».

| | PageSpeed 02.11 | Наш прогон прода, `/en` | Наш прогон прода, `/ru` |
|---|---|---|---|
| Производительность | 95 | 81 | 92 |
| Доступность | 96 | 96 | 96 |

| SEO | 100 | 100 | 100 |

Прогон — Lighthouse 13.4 из `services/web` (`npx lighthouse https://iqro.forum/en`) с той же

наши. Вес и список запросов воспроизводятся точно.

## Причины и решения

### Портреты чтецов — 12,6 МБ из 13

Портреты загружены в админке как PNG 1254×1254 по 2–2,8 МБ, а показываются в кружке не
больше 112 CSS px. Сайт и приложение брали один и тот же исходник по `portrait_url`. На `/ru`
сетка популярных чтецов в первый экран не попала, поэтому Lighthouse их не скачал, а на `/en`
скачал восемь штук.

Сделано: backend при загрузке сохраняет две WebP-копии — 640 и 320 px по короткой стороне
(ffmpeg, как у миниатюр объявлений). API отдаёт `portrait_url` (640 px) и новое
`portrait_thumbnail_url` (320 px), исходник остаётся в хранилище. Сайт показывает в аватарах
копию 320 px, для обложки в системном плеере — 640 px. Приложение выбирает копию по нужному
числу пикселей: 320 px, если её хватает для размера на экране, иначе 640 px. Уже выпущенные
версии приложения получают копию 640 px через тот же `portrait_url` без обновления.

Для 22 портретов, загруженных раньше, копии создаёт команда
`generate_reciter_portrait_variants`. Локальный прогон на настоящих исходниках с CDN: 39
WebP-файлов, 1,1 МБ на всех вместо ~25 МБ; повторный запуск ничего не меняет. На проде её
нужно запустить отдельно ([operations.md](operations.md), «Уменьшенные копии портретов
чтецов»).

Ожидание после выкладки и запуска команды: восемь портретов на `/en` весят 102 КиБ вместо
12 663 КиБ, вся страница — около 810 КиБ вместо 13 374 КиБ (расчёт по списку запросов
нашего прогона с реальными размерами копий).

Выложено 02.11.2026 (main `220ff79f`, миграция `0017_reciter_portrait_variants`), перед этим
бэкап базы с копией в облако. Команда сначала без флагов («22 portraits need copies»), затем с
`--apply`: копии есть у всех 22, повторный запуск — «0 portraits need copies». У
`qf-175-abdullah-hamad-abu-sharida` копия 640 px не меньше исходного JPG (37 КБ), поэтому
`portrait_url` остаётся исходником, а миниатюра — WebP 17 КБ. Пример: Махмуд Халиль аль-Хусари
был 2,8 МБ, стал 29 КБ (640 px) и 8 КБ (320 px).

Замер Lighthouse 13.4 по проду после выкладки, мобильный профиль:

| Производительность | 81 | 92 | 91 |
| Доступность | 96 | 100 | 100 |

### Доступность 96 → 100

Подпись `.surface-subtitle` на светло-зелёном фоне в мобильной теме имела контраст 4,49 при
норме 4,5. Токен `--text-muted` мобильной темы стал чуть темнее: `#636c63` → `#5c655c`
(контраст на всех фонах темы 5,0–6,0).

### Ошибка в консоли: `web-auth/refresh` → 401

При первом визите сайт пробует восстановить сессию, а у гостя её нет. Теперь BFF отвечает
`204 No Content`, если cookie сессии нет вовсе, и клиент считает это «сессии нет». Истёкшая
или отозванная сессия по-прежнему отвечает 401. Проверка консоли в e2e больше не разрешает
этот 401.

### Анимация точки «Гостевой режим»

Пульсирующее кольцо было анимацией `box-shadow`, браузер перерисовывал шапку каждый кадр.
Теперь кольцо — псевдоэлемент, который меняет только `transform` и `opacity`.

## Что не менялось и почему

- **Блокирующий CSS (~0,9 с по оценке).** Все стили сайта подключены в корневом layout:
  ~37 КБ сжатого CSS, на главной не используется около 20 КБ. Разнести их по разделам можно,
  но нужно проверить порядок каскада на всех страницах — это отдельная работа (tech-debt,
  раздел 2). `experimental.inlineCss` хуже: 170 КБ CSS ушли бы в каждый HTML.
- **Шрифт 107 КБ на критическом пути.** Это арабский Amiri для арабского текста на главной.
  Он грузится с `font-display: swap` и не задерживает отрисовку; ужать набор символов — уже
  пункт tech-debt.
- **«Устаревший JS» и неиспользуемый JS.** Полифилы — встроенный модуль Next.js, который
  подключается всегда; неиспользуемый код — общий рантайм Next и React. Безопасной настройки
  нет.
- **Пузырёк объявления** крутит три анимации на одном элементе — переделка с дизайном
  объявлений (tech-debt).
- **CSP, HSTS, Trusted Types.** Строгий CSP с nonce ломает ISR, Trusted Types требует проверки
  сторонних скриптов, `preload` в HSTS почти необратим. Предложено отдельными PR с решением
  владельца (tech-debt).

## Проверка в CI

Lighthouse CI (`npm run test:lighthouse`) гоняет страницы на тестовых данных без портретов
из админки, поэтому вес картинок там не изменился. Доступность на всех 14 страницах стала
98–100 (лендинги 96 → 100), поэтому порог `accessibility` в `lighthouse-budget.json` поднят
с 0,95 до 0,98. Остальные бюджеты не менялись.

## Новая главная: HTML в первой порции данных (07.11.2026)

Новая главная (небо намаза, крупные разделы, PR #220) сначала не прошла бюджет LCP 4000 мс
на `/ar` и `/tr` (4070–4090 мс). Главный элемент тот же — картинка шапки, но первая отрисовка
сдвинулась на ~150 мс: сжатый HTML главной вырос с ~13,6 до ~16 КБ и перестал помещаться
в первую порцию данных TCP (Lighthouse считает её 14 600 байт с заголовками), поэтому
документ приходил за два обмена.

Решение — не рисовать в HTML то, что всё равно появляется только в браузере или ниже первого
экрана:

- **Небо намаза.** Времена намаза приходят из браузера, поэтому в HTML — только пустая полоса
  того же цвета и высоты (`.home-sky-placeholder`, 207 px), а заголовок, кнопки и рисунок
  появляются после загрузки скрипта. Строка «Через …» держит своё место и пока времена
  грузятся (пустая строка), поэтому полоса не растёт ни при загрузке скрипта, ни при приходе
  расписания: 207 px на телефоне, 208 px на широком экране.
- **Сетка разделов.** Плитки с линиями иконок (~1,1 КБ сжатого HTML) стоят ниже первого экрана
  и рисуются в браузере; заголовок «Разделы» остаётся в HTML.

После этого сжатый HTML главной на тестовых данных: `/ru` 14,5 КБ, `/en` 13,4, `/ar` 14,1,
`/tr` 13,8 (с заголовками), первая отрисовка снова как на `main`, LCP 3,6–3,9 с. Бюджеты не
менялись. **Правило для главной:** всё, что добавляется в HTML первого экрана, должно
укладываться в этот запас (на `/ru` около 120 байт); остальное — рисовать в браузере.
