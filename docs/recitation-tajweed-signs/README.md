## Коротко

1. **Таблица ожидаемых звуков знает почти все правила.** Её строит готовый движок правил, который идёт
   вместе с моделью, а не наш ручной код. В ней записаны ихфа, икляб, идгам, калькаля, все мадды с длиной,
   сакта в двух местах, имала, тасхиль, чтение «отрезанных букв» в начале сур.
2. **Плашка использует малую часть этого.** Она останавливается, когда пропущено слово, прочитана другая
   буква или другая огласовка, почти пропущена гунна на نّ / مّ или мадд муттасыль прочитан вдвое короче.
   Нарушения остальных правил проходят без остановки — это подтверждено замером (раздел 5).
3. **Причин три, и они разные по цене:**
   - *плашка не сравнивает длину звука* (кроме гунны и муттасыль) и *не замечает лишний звук внутри слова* —
     это наш код, исправляется без дообучения модели;
   - *один несовпавший звук в слове прощается* — так сделано, чтобы не было ложных остановок; из-за этого
     пропущенная калькаля или ихфа, прочитанная ясным нуном, проходят;
   - *модель чего-то не слышит совсем*: сакту, ималю, тасхиль, длину больше четырёх счётов, тафхим и таркик —
     тут нужна другая или дообученная модель.
4. **Знаков остановки в тексте экрана проверки нет вообще.** Они есть только в рисунке шрифта Мусхафа и в
   тексте с цветным таджвидом. Плашка про них не знает; остановка посреди аята сейчас даёт ложную ошибку
   (этим занят PR #307).
5. **Есть место, где правильное чтение считается ошибкой:** имала в 11:41 — у всех трёх чтецов плашка
   покраснела на слове «мадж̱рэ̄hа̄».
6. **Остановка в конце аята учтена:** каждый аят записан в таблице так, как он читается с остановкой на
   последнем слове (огласовка и танвин не читаются, «‑ан» → долгий «а», ة → «h», калькаля, мадд ‘арид).
   Не учтено обратное — слитное чтение двух аятов без остановки (раздел 4, последняя строка).
7. **Гунна там, где её быть не должно, не ловится** (нашёл владелец на живом чтении, 20.11.2026): в
   «عَذَابٌ عَظِيمٌ» он протянул «н», и плашка не остановилась, хотя это ошибка — при изхаре «н» короткий и
   ясный. Замер подтвердил: плашка остановилась 1 раз из 44. Модель при этом разницу слышит (34 из 44),
   то есть правило можно включить без дообучения (раздел 5.4).

## Как устроена проверка — в трёх шагах

1. **Таблица.** Для каждого из 6236 аятов заранее записано, какие звуки должен дать правильный чтец:
   буквы, огласовки, долгие гласные (по одной букве на счёт: `اا` — два счёта, `اااا` — четыре) и особые
   звуки. Пример, 2:3: `…وَمِممممَاارَزَقڇنَااهُميُںںںفِقُۥۥۥۥن` — здесь `مممم` это гунна, `ڇ` калькаля, `ںںں`
   ихфа, `ۥۥۥۥ` мадд ‘арид в четыре счёта.
2. **Модель** слушает микрофон и 50 раз в секунду говорит, какой звук из 42 она сейчас слышит.
3. **Плашка** идёт по словам: проверяет, что звуки слова прозвучали *по порядку*. При этом повторы одного
   звука склеиваются (`اااا` и `اا` для неё одно и то же), один несовпавший звук в слове прощается, а лишние
   звуки между ожидаемыми не считаются.

Поэтому у каждого знака ниже три ответа: (а) что записано в таблице, (б) останавливает ли плашка,
(в) чем это подтверждено.

Особые звуки в таблице (всего по Корану): `ں` ихфа — 5305 мест, `ڇ` калькаля — 3837, `۾` скрытый мим
(икляб и ихфа шафави) — 1058, `ۜ` сакта — 2, `۪` + `ـ` имала — 1, `ٲ` тасхиль — 1.

Пояснения.
- Остановка посреди аята (на любом знаке) меняет конец слова: танвин и последняя огласовка не читаются,
  ة становится «h», появляется калькаля. Таблица на main знает слова только в слитном чтении, поэтому
  остановка даёт красную плашку. Это видно и на моих записях: 41:44 — у всех трёх чтецов ложная остановка
  на слове перед «أَأَعْجَمِىٌّ», 10:51 — у всех трёх на «بِهِ», 2:245, 7:69, 30:54 — то же (`out/06`). PR #307
  разрешает остановку на любом слове; сам знак (можно / нельзя / обязательно) он не учитывает.
- Сакта: модель её не слышит — у трёх чтецов в 75:27 и 83:14 она ни разу не написала знак паузы (0 из 6,
  `out/04`). Плашка из-за этого не краснеет: один неуслышанный звук в слове прощается (0 ложных остановок
  на 6 чтениях, `out/06`). Но и слитное чтение «мар-ра̄қ» она не поймает (`out/07`, строка «no_sakt»).
- В тексте экрана («А») сакта в 18:1, 36:52, 75:27, 83:14 не обозначена вовсе: читающий её знак не видит.

ожидается один. Порог нужно подобрать на живом голосе: замедленная запись звучит не так, как человек,
который тянет «н» сам.

## 6. Найденные неточности

1. **11:41, имала** — правильное чтение считается ошибкой (раздел 5.3). До решения проще всего записать это
   слово в таблице так, как его слышит модель, чтобы плашка не краснела зря.
2. **19:1 и 42:2, буква ‘айн** — её протяжный «й» в таблице помечен как место «идгам с гунной». Чтец,
   прочитавший ‘айн в два счёта, может получить красную плашку за «короткую гунну». Не проверено замером:
   все три чтеца читают длинно.
3. **Сакта не видна читающему**: в тексте экрана нет её знака в 18:1, 36:52, 75:27, 83:14.
4. **36:52** — в таблице между «مَّرْقَدِنَا» и «هَٰذَا» ничего нет: ни сакты, ни остановки.
5. **10:51, ءَآلْـَٰٔنَ** — в таблице мадд шесть счётов. Аль-Миншави читает здесь тасхиль (оба способа
   допустимы), и модель слышит другое. В длинном аяте это теряется за ложной остановкой на вакфе.
6. **Слитное чтение аятов** не предусмотрено: каждый аят записан с остановкой в конце.

Ничего из этого я не исправлял.

Сначала — что нужно читающему чаще всего и что не требует новой модели.

8. Лишний звук внутри слова (гласный на сукуне, прочитанный лям шамсия, нечитаемая буква).

## Как повторить

Нужны: файлы модели с её страницы на Hugging Face (`config.json`, `imam.py`, `onnx/model-int8.onnx`),
Python с `numpy onnxruntime faster-whisper quran-transcript levenshtein`, записи с everyayah.com в виде
`<чтец>/<SSSAAA>.wav` (16 кГц, моно). В git этого нет.

```bash
python scripts/census.py <репозиторий>                         # out/01, пишет table_text.json
python scripts/census_tajweed_text.py taj.json                  # out/02
python scripts/units.py <папка модели>                          # out/03
MODEL_DIR=… python scripts/hear.py ../recitation-on-device-spike/scripts <записи> …   # out/04
APP=clients/iqro_mobile python scripts/look.py 11:41 75:27      # out/05
python scripts/own_cases.py <записи> <папка случаев> clients/iqro_mobile/assets/recitation_model/expected.json
python scripts/mutate_cases.py clients/iqro_mobile/assets/recitation_model <чистые случаи> <папка> 20
dart run tool/recitation_model/harness.dart <libonnxruntime> <model-int8.onnx> <таблица> <случаи> -v > run.txt
python scripts/parse.py <папки случаев…> -- run*.txt            # out/06, out/07
MODEL_DIR=… python scripts/izhar_stretch.py ../recitation-on-device-spike/scripts <папка случаев> <expected.json> <записи> …   # out/08
```

Стенд считает медленно: примерно секунда на секунду записи на одно ядро.
