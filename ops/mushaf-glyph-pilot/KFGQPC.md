# KFGQPC HAFS — существующий Quran.Foundation resource 5

Этот адаптер использует **существующий backend snapshot**, а не JMApps QCF и не
повторный импорт Корана. Изменения чтецов, аудио, canonical UUID и пользовательских
загрузок не требуются. Исходный Unicode и номера строк сохраняются. Заголовки сур
берутся из canonical каталога; вводная басмала — четыре исходных слова 1:1.
Шрифт один для текста, заголовков и басмалы: официальный `UthmanicHafs1Ver18`.

## Воспроизводимая подготовка

1. `python manage.py export_qf_mushaf_source --mushaf 5` выводит только публичный
   snapshot. PostgreSQL-транзакция repeatable-read/read-only. Сохранить вывод в
   **новый** `snapshot.json`, не поверх прежних файлов.
2. Скачать `font_url` из `kfgqpc.source.lock.json` в новый каталог. Проверить SHA
   шрифта и snapshot по lock. WOFF2 (87 760 байт) декодируется в памяти; файл не
   переписывается и не включается в APK. Для Python дополнительно нужен Brotli 1.2.0.
3. Runtime тот же, что для QCF: fontTools 4.43.0, uharfbuzz 0.56.1, HarfBuzz 14.4.0;
   raster sharp 0.35.4 / libvips 8.18.6 / librsvg 2.62.91 / libwebp 1.6.0.
4. `python3 ops/mushaf-glyph-pilot/kfgqpc.py --source-dir SOURCE --output-dir NEW_BUNDLE`.
   `--audit-only` проверяет геометрию всех страниц без растров;
   `--pages 1,3,77,604` создаёт sample, который нельзя опубликовать как полный набор.
5. Полный набор: 604 страницы, все 6236 аятов, WebP 720/1440/2160 и области нажатия.
   Partial results возобновляются только с тем же кодом/входными хешами. Ни один
   существующий файл автоматически не очищается и не перезаписывается.
6. Backend `publish_mushaf_rendition MANIFEST --validate-only`, затем штатная
   публикация после backup/проверок. Проверяется совпадение с текущим QF snapshot
   до подготовки и под блокировкой строки перед атомарным включением.

## Проверки источника

- 604 страницы, 114 сур, 6236 последовательных verse identities; все слова и
  завершающие номера аятов проверяются без восстановления недостающего текста.
- QF word 621307 (2:181) содержит правильный номер `١٨١`, но тип `word`, не `end`.
  Аудит распознаёт числовой маркер по **существующему** тексту. Ничего не добавляет.
- В отдельных страницах первый аят начинается на строке 2. Для заголовка
  резервируется отдельная верхняя строка, без удаления слов или басмалы.
- Контуры сохраняются под равномерным масштабом, все знаки обязаны существовать
  в исходном шрифте. Hit regions получены из тех же контуров/строк, без наложений.
- Смена source checksum скрывает устаревшее QF-оформление в API, но не удаляет
  файлы, существующий Мадинский Мусхаф или отдельное JMApps QCF оформление.

Это **композиция IQRO с оригинальным KFGQPC-шрифтом**, не заявление о пиксельном
совпадении с официальной печатью. Публикация пока ограничена staging. Production
контентный review/условия файлов фиксируются отдельно; не менять флаг вручную.

## Тестирование

`IQRO_KFGQPC_SOURCE_DIR=SOURCE python3 -m unittest discover -s ops/mushaf-glyph-pilot -p test_kfgqpc.py`

Полные существующие backend/Flutter bundle-тесты принимают `kfgqpc-hafs` и
проверяют все 1812 файлов, canonical ayah IDs и попадания тапов. В обычном прогоне
без пути к полному набору эти тесты пропускаются, а не объявляются выполненными.
